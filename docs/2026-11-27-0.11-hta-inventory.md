# HTA (holoscan-tcn-applications) use of tcn_schema 0.10.7: inventory for the 0.11 breaking release

Scope: tcn_schema 0.10.7 (`share/tcn_schema/dds/` of the package, this repository at main),
sqe_client_cpp 0.6.2 (recipe only in the Conan cache; headers read from the sibling `sqe_client/` packages: `client.h`, `cdr_codec.h`,
`zenoh_transport.h`, `pose_attachment.h`), contract headers `tcn/sqe/*.h`. Read-only inventory, nothing run against live services.
Paths are relative to the holoscan-tcn-applications (HTA) repository. Line numbers are as of HTA main `f46cb756` (approximate).

Findings up front:
- tcn_schema 0.10.7 ships **no FlatBuffers**: only `dds/*.idl` (+ `JointSets.md`) and the `tcn/sqe` contract headers. All `tcn.*` FlatBuffers
  (`tcn.CameraCalibration` etc., `schemas/*.fbs`, 35 files) are **HTA-owned** (recordings, graph edges, HoloMQ). Several are field-for-field
  mirrors of tcn_schema IDL types (table in §1.8), which a schema change therefore also breaks.
- HTA has **no generated Python bindings** of tcn_schema. Python sees descriptors, fragments, targets as `dict`s built in nanobind C++ (§4).
- `conversation_msgs`, `device_hl2_msgs`, `device_orbbec_msgs`, `geometry_msgs`, `tf2_msgs`, `statistics_msgs`, `shape_msgs`, `rosgraph_msgs`,
  `unique_identifier_msgs`, `Logging.idl`, `HumanPose.idl`, `TimeRef.idl`, `XRInput/XRRuntime/HandTracking/AudioStream/CameraModel(CameraInfoMessage)`:
  **not used by HTA**. Of `std_msgs` only `Header`; of `sensor_msgs` only `PointCloud2`(+`PointField`).

Legend for "HTA uses it to": P publish, S subscribe, St store (config/registry/state), R record (via HTA FlatBuffers mirror), C config/convert.

## 5. Workarounds and pain points

Each item: what / where / what a schema change could fix.

**P1. Domain carried inside `SRNode.name` as a string (`@{domain}::{name}`); re-implemented three times.**
- Where: design 81 §3.1, §7 items 16, 11; `sqe_link.cpp:176-211` (C++ helpers, stricter than `tcn::sqe::check_domain`: no `.`/`..` chunks, no chunk starting/ending with `:`); `python/holoscan_tcn/sqe_domains.py:59-134`; the web controller; `default_role()` guesses a node's role from a name regex `.+_(depth|color)(_image)?` (`sqe_domains.py:110-116`); marker template instances use `...:::*` (design 81 §7.1, `@d:::a` ambiguity).
- Cost: every consumer parses `@`, `::`; an `SRNode`'s plain name is no longer the bare name; a `SISFrameRef` with a domain node needs an empty `client` (design 81 §7 item 6, 13: "a client given with a frame that resolves to a domain node is dropped with one warning").
- Fix: the queued `SRNode.domain` field (MIGRATION-0.10.7 "Planned 0.11"), a `domain` on `SISFrameRef` / `SREdge.source|target` references, and `domain` on `SRNodeTemplate`/descriptor for marker spaces.

**P2. `marker_system` is a packed string: `<family>:<dictionary>` + replay prefix `replay.` + `@<space domain>`.**
- Where: `libs/transport/sqe_link/src/sqe_link.cpp:338-352` (`marker_system_for`: `prefix + "." + system + "@" + space`), `:345-348` (`marker_system_part` splits at last `@`); `sqe_marker_camera_op.hpp:92-104`; design 81 §3.1 "Marker space", §7 item 26; request `2026-11-27-sqe-rational-lens-and-marker-spaces.md` §2 option 3 ("Encoded in marker_system until then: no schema change, but the engine must strip it before the registry lookup"). B94 additionally rewrites the string (`:`, non-identifier bytes -> `.`) into node names `_mtarucom_aruco.DICT_4X4_50___sis_marker__7`; HTA must call `marker_node_name(kind,id,system)` and must give the *system part only* for the `cfg/marker` token (`sqe_marker_camera_op.cpp:128`).
- Also: the same 6-value `MarkerType` is mirrored in the contract (`tcn::sqe::MarkerKind`) and in HTA (`sqe_marker_camera_op.cpp:44-51`); the ordinal of a kind "renames every node a tracker of that kind ever created" (`Types.idl` comment).
- Fix: separate `marker_family`, `marker_dictionary`, `marker_domain` fields on the descriptor; node naming from structured parts; drop the ordinal-as-name coupling.

**P3. Closed enums and version gating by `op/info protocol_break`.**
- Where: `SRNodeScope` ordinal 2 broke the web controller decoder (`requests/2026-11-27-web-controller-sqe-domains.md`); MIGRATION-0.10.7 asks readers to "treat an unknown scope as shared". HTA gates features on the engine's B-number: `kRationalLensBreak = 96`, `kDomainTemplateBreak = 95`, `kMarkerSpaceBreak = 97` (`sqe_link.hpp:350-357`), `engine_protocol_break()` asked once per epoch over a separate operator query (`sqe_link.cpp:550-585`). An engine that cannot read a model/scope refuses the *whole join* (design 81 §7 item 2), so HTA must pre-check (`projection_intrinsics`, `sqe_link.cpp:281-336`). Design 81 §7 item 14: apps cannot warn about a B94 engine with markers because `EngineInfo` has only id/epoch/liveness.
- Version pins: `conanfile.py:141-149` ("sqe_client_cpp 0.6.2 requires exactly this version"); the wire annotation `;tcn_schema=0.10` refuses any other minor, so design 70 shipped 0.10.5 not 0.11 (`docs/migration/70-tcn-schema-0.10.5-notifications.md` §1). A 0.11 break means the engine, sqe_client and every peer rebuilt together.
- Fix: capability/feature set in `SISEngineInfoReply` (+ in the join reply), an "unknown ordinal" decoding rule in the spec, additive-only enums with an explicit `UNKNOWN`, and a negotiated version instead of minor equality.

**P4. Duplicated and lossy camera intrinsics (CameraSensor.CameraModel vs SRIntrinsics vs VideoStream vs HTA `tcn.CameraCalibration`).**
- Where: `schemas/camera_calibration.fbs:1-40` (`Intrinsics` pinhole + `coeffs[8]` BROWN_RATIONAL order k1,k2,k3,k4,k5,k6,p1,p2 + `metric_radius`); `libs/transport/sqe_link/include/tcn/sqe_link/camera_calibration.hpp:30-47` reorders to OpenCV `k1 k2 p1 p2 k3 k4 k5 k6`; `calibration.cpp:26-60` (CameraModel from the ArteKMed JSON `radial_distortion.m00..m50` + tangential `m00,m10`); `VideoStreamMessage` carries only `radial[3]`/`tangential[2]` which HTA neither writes nor reads (`frame_serde.cpp:23-37`).
- Pain: `SRIntrinsics.distortion_model` documents `opencv_fisheye` that no engine implements (design 81 §7.2, request 2026-11-27 §1); until B96 every Azure Kinect (rational, k4..k6 != 0) got **no projection edge** (`sqe_link.cpp:319-325`); no validity radius (Azure `metric_radius`); Azure's p2-before-p1 order; `CameraModel.radial_coefficients[8]` has no model-order statement.
- Fix: one shared `CameraIntrinsics` (model enum incl. rational/fisheye, documented coefficient order, `metric_radius`, double precision) used by `CameraModel`, `SRIntrinsics`, `VideoStreamMessage`, and a note in the IDL of which engines read which model.

**P5. `StreamDescriptor.buffer_info.properties` as a generic bag (name, int32, bytes).**
- Where and what is packed:
  - H.26x codec data: property `h26x_codec_data`, user_data key `data` = Annex-B parameter sets, put after the first keyframe (`zenoh_publisher_op.cpp:349-364`, "As ArteKMed's encoders").
  - pose target-name map: `target/<name>` = id (`pose_wire.cpp:95-125`, `pose_wire.hpp:8`; the wire has numeric ids only).
  - persons descriptor: `world_frame`, `handedness`, `units`, `joint_set` (+count as value), `up` ("x,y,z" text), `smoothing`, `min_cutoff_hz`, `beta`, `d_cutoff_hz`, `bone_tol`, `rate_hz` (numbers formatted into text; `person_track_publisher_op.cpp:62-101`; request in `70-tcn-schema-0.10.5-notifications.md`).
  - mesh: `vertices_capacity`, `faces_capacity`, `num_cameraids` (sic) plus magic `semantic_type = 0x2100000401034243` and `frame_size = width = stride = ZSTD bound`, `height 1`, `bits_per_element 8` (`mesh_bitstream/src/stream.cpp:24-50`, `stream.hpp:15-18,36`).
  - surfels (`SENSOR_TYPE_SURFEL`): only `is_fixed_size(false)`, layout implied by PointCloud2 fields.
- Fix: typed per-`sensor_type` descriptor sections (codec parameters/`codec_data`, `target_names`, person-set properties, mesh capacities) or a typed variant property; stop abusing `semantic_type` as a magic number.

**P6. Descriptor fields that cannot say what HTA needs.**
- `h26x_profile` doubles as codec selector (H264 vs H265): receivers "pick the codec from the profile" (`zenoh_publisher_op.cpp:79-83`, `zenoh_bindings.cpp:141-148`).
- IR vs depth: both are `L16`; `sensor_type` disambiguates; mono8 streams get `SENSOR_TYPE_NONE` (`zenoh_publisher_op.cpp:56-61`).
- Mesh descriptor schema name is `tcnart_msgs::msg::MeshBitstreamMessage` while the data is `pcpd_msgs::msg::MeshBitstreamMessage` ("sic", `stream.hpp:15-16`); MeshStream v2 reuses the message with `vertex_size_bytes = 0` and `data` = another format, type name `tcn::MeshStreamV2Message` (`mesh_stream.hpp:35-37`, design 39 §Container).
- The descriptor of an IR stream has no width/height catalog (design 79 §Tracking-services: "the catalog has no width / height").
- `calib_topic` is filled only in the tcnart profile; `calib_topic_schema` never.
- Fix: codec enum separate from H26x profile (H264/H265/JPEGLS/ZDEPTH/NDQ...), a depth/IR flag in pixel semantics, correct schema names, a first-class mesh stream message.

**P7. Time: int32 seconds, one stamp per message, no group id, no device/host pairing on the wire.**
- Header `Time.sec` int32 wraps in 2038 (`person_wire.hpp:6`, `mesh_bitstream/src/stream.cpp:59-62`, `frame_serde.cpp:33`).
- `TargetTrackingMessage` has no per-target stamp: HTA stamps the message with the earliest entry and drops per-entry times (`pose_wire.hpp:35-39`, design 51 §Data tracks "the wire has no per-target stamp, no schema change").
- No group/sequence id on video/mesh streams: receivers regroup by time tolerance (`python/holoscan_tcn/zenoh_rig.py:61-87`, StreamGroupOp `fill_missing`, mesh `stream.hpp` "clients match colour/depth by it"); only `PersonTrackingMessage.group` has one. Internally the group id lives in `SampleMetadata.frame_id` (`applications/capture/capture_server/python/capture_server.py:15`, `replay_server.py:13`) and is lost on Zenoh.
- Clocks: `clock_domain` is a free string, empty by default and left empty by every HTA camera/mesh descriptor; only person and SQE tracker descriptors expose it (`person_track_publisher_op.hpp:33`, `sqe_tracker_op.cpp:126`); `sensor_latency_ns` and `CameraSensor.timestamp_offset_ns` are never used by HTA. HTA's recordings keep device/host pairs in its own `tcn.DeviceTimestamp` (`schemas/device_timestamp.fbs`) and guard device clock drift (design 78 §R16: 825 s over a take).
- Fix: `int64` seconds (or ns), `group_id`/`sequence` + `capture_time` + `device_time` in a shared stream header, per-target `stamp_ns`, structured clock domain (id, kind, offset).

**P8. `header.frame_id` overloaded.**
- Used as a camera frame (`camera01_color`, `capture_camera_op.cpp:403,917`), the SQE device node name (`sqe_tracker_op.cpp:295`: `m.header().frame_id(device_node(p))`; marker camera `:458`), `"world"` for clouds/meshes (`surfel_estimate_op.cpp:613` etc.), `"mosaic"`, and ignored for persons (`world_frame` carries the frame; `person_wire.hpp:6`). The descriptor's `header.frame_id` is the stream frame again (`pose_wire.cpp:105`).
- Fix: explicit `frame`/`node` reference fields (with domain) instead of a free `frame_id`.

**P9. Pose messages: names, per-target time, covariance frame/order, `target_origin`.**
- Names only via descriptor property map (P5); ids = list index (`sqe_tracker_op.cpp:67` `stream_item_id(i)`).
- `target_origin` is dropped by the SQE; HTA sets identity (`sqe_tracker_op.cpp:296`).
- Covariance order (tx..rz) vs HTA's tracking order (rx..tz): 6x6 permutation both ways, the frame "is not named by the IDL" (`pose_wire.hpp:11-14`).
- `quality = 1`, `is_tracked = true`, no markers ever (`pose_wire.hpp:7-8`).
- Fix: name in `Target`, per-target stamp, covariance frame/order stated, remove or define `target_origin`.

**P10. Persons and skeletons.**
- `joint_set` is a free `string<64>` key into `JointSets.md` (`coco17`, `halpe26`, `tcnart_body_v1`); HTA's joint counts hard-coded (`person_track_publisher_op.cpp:55-60`, `libs/geometry/body/include/tcn/body/skeleton.hpp:63-65`); fixed bounds (16 persons, 32 joints, 8 cameras) enforced by HTA, not by fastcdr (`person_wire.hpp:18-22`).
- Rotations (`joint_rotations`, `root_orientation`) exist but are not produced; design 70 "SMPL parameters are never sent" and design 79 "Prepare for SMPL on the wire (a possible future extension)" want a typed SMPL pose/shape field (`docs/migration/79-pose-tracking-sqe-slots-design.md` Decisions).
- SQE has no dynamic targets: persons enter the graph as N fixed `person_<k>` Global nodes via a slot-mapping converter, heading-only orientation, hip joint only (design 79; `operators/perception/person_slots`).
- `role` int16 / `role_confidence`: reserved, not produced. `HumanPoseMessage`, `TimeRef*` unused.
- Fix: joint-set enum/registry as IDL, SMPL/rotation fields, SQE-side dynamic target creation from a tracked-list stream.

**P11. Calibration revisions and provenance have no wire home.**
- `pcpd_msgs::CameraSensor` has no revision/provenance; its poses are in ArteKMed's OpenGL camera frame (y-up, -z forward): HTA converts with `F = Rx(180 deg)` (`schemas/camera_calibration.fbs:5-14`, `operators/perception/person_pose/include/tcn/operators/person_pose_backend.hpp:59`).
- `SRCalibration` (method, residual, computed_at, covariance) is never set: HTA uses `STATIC_CALIBRATED` with no provenance; its own `tcn.SpatialCalibration` has `revision`, `source`, `method`, `residual_mm`, `note` (`schemas/spatial_calibration.fbs:13-35`; design 80 §Variant A vs B "the metadata only in CALIB_'s free-text source/method/note").
- Live calibration change travels as HTA JSON `calibration/set` + `calibration/changed` `{"revision": int, "cameras": [...]}` (design 79 conventions P79-R2, `calibration_rpc.hpp:1-30`); the tracking-ownership check uses a JSON queryable `<rpc>/tracking` `{"ir_track", "markers"}` ("not a describe field: the describe reply is fixed pcpd_msgs messages", P79-R1).
- `depth_units_per_meter` is not stored in the export: HTA defaults to 1000 (`calibration.cpp:82`, `calibration_file_source_op.hpp:29`).
- Fix: `revision` + provenance in `CameraSensor`, a declared coordinate convention, typed `CalibrationSet`/`CalibrationChanged`/`TrackingState` RPC messages, use of `SRCalibration` by engines/clients.

**P12. JSON side-channels where the IDL has no field.**
- `StreamAnnouncementReply` has no transport/host/endpoint/catalog/slots; the JSON form carries them, the CDR "has no field for them" (`parameter_service.cpp:975-987`, design 36 keys).
- Parameter protocol: JSON layout is "byte-for-byte ArteKMed's" with only an informal mapping (`json_codec.hpp:1-9`, MIGRATION-0.9.0); Python re-types the ordinals (`params_client.py:55-67`); `ParameterValue` has `PVT_STRUCT` that no one produces (`json_codec.cpp:31`); `ServiceInfo.service_info` is a free string `"HoloscanParameterService"`.
- Fix: specify the canonical JSON mapping in the repo, add the missing fields to `StreamAnnouncement`, give Python generated enums.

**P13. Wire typing profiles and attachments.**
- Two profiles (artekmed: type as attachment, `cfg/dsc`, `_image_bitstream`, descriptor as queryable; tcnart: type in encoding, `cfg/desc`) (`wire_profile.hpp:14-18`, `wire_profile.cpp:98-107`); the engine's 13-byte relation-pose attachment collided with "attachment = type name" and broke `PoseSubscriberOp` until `check_wire_type` was changed (design 38 §after B83: "an engine relation pose carries its 13-byte binary pose attachment there (B80)"). HTA re-implements `check_wire_type` rather than use the contract's `parse_encoding`.
- `tcn::sqe::WireType<T>` registers only SQE + 3 tracking types; HTA hand-writes the type name strings for VideoStream, PersonTracking, PointCloud2, DeviceContextReply, ParameterChanged (`put.attachment = "tcnart_msgs::rpc::ParameterChanged"`, `parameter_service.cpp:1482-1490`).
- Fix: one profile, `WireType<T>` for every wire message (incl. pcpd/ArteKMed ones), attachment reserved for data.

**P14. Descriptor order, re-announce and marker race.**
- The descriptor must be put before the claiming join; the engine fetched descriptors only at start-up until B83 (design 38 §Part C, "announce the descriptor again once the claiming part is joined" as workaround). With a changed `marker_system` a re-announced descriptor was ignored ~1 in 4 runs; HTA now removes the part, waits for the join answer + 500 ms, then re-puts (request 2026-11-27 §3). `cfg/marker` liveliness tokens carry the node name, so two spellings of one marker are two nodes (`tracker.h` comment).
- Fix: explicit descriptor version/epoch in the message, a re-read rule, marker announce by `(system, id)` instead of node name.

**P15. Node naming conventions parsed by convention, not schema.**
- D6 target names `<target>_<device lower>` (`_irtrack`, `_ndi`, `_art`), device names `IRTRACK/NDI/ART/POSETRACK`, `<camera>_depth|_color|_depth_image|_color_image`, `world`, `person_<k>` (design 60 §D6, design 81 §3.1, `sqe_link.cpp:350-353`), the rig `camera01..` ids; HTA's `default_role()` and the Python static-edge files infer a role from these names. Registry kind passed as string (`rigid_body|fiducial|board|device`, `sqe_state_op.cpp:90-97`).
- `SRNode` carries `display_name`/`description`/`custom_data` that HTA never uses; the convention lives in docs (`requests/2026-11-25-tracking-services-conventions.md` §4).
- Fix: node `role`/`kind` fields beyond the 5-value `SRNodeType`, `physical_object` link, or at least a normative naming section in the schema.

**P16. Coordinate system fixed to OpenCV for every node.**
- `make_node` writes `right=X_POS, up=Y_NEG, forward=Z_POS` on every node incl. `world` (`sqe_link.cpp:226-237`), and 2-D image planes use `dimensions=2` meaning u right / v down (design 81 §7 item 3). The persons stream names its own `up` vector (`PersonTrackingMessage.up`, per site) because world axes are not per-site defined in the graph.
- Fix: presets/handedness in `CoordinateSystem`, per-node real axes, a documented relation to `PersonTrackingMessage.up`.

**P17. Large-payload CDR handled by hand.**
- `VideoStreamMessage` has `image_bytes` (u64) and then `sequence<uint8> image`; HTA builds the CDR prefix itself and patches the two length fields in place so that the payload can be sent from shm without a copy (`frame_serde.cpp:50-95`, `kLengthFields = 12`). Same for the point-cloud encoder (`point_cloud2.hpp`: "byte-for-byte as `encode(make_cloud2(...))` but with one copy").
- `PointCloud2` is used for surfels with HTA's field conventions (x y z nx ny nz r, optional `rgb`, `class_id`, `instance_id`) and `SENSOR_TYPE_SURFEL` (`point_cloud2.hpp:15-20`).
- Fix: payload as a separate Zenoh attachment/second sample, or a bytes member at the tail documented as zero-copy; a typed surfel message.

**P18. Recording metadata and the FlatBuffers mirrors.**
- Every IDL change forces edits to the mirrors in §1.8 (design 66 "field for field"); `PersonJoint.age_s` was kept as a separate array because "a struct cannot grow without breaking recorded lists" (`person_track_list.fbs`). Eye/IMU `valid` bitmasks are copied as plain integers.
- Fix: stable IDs for recorded types, or a recording-friendly schema dialect (FlatBuffers-first IDL).

**P19. Misc small ones.**
- `std_msgs::Header` must be decoded alone to find the CDR image offset (`frame_serde.cpp:71-75`).
- `TcnartPresenceMessage.services[].topic_prefix` is used as the service root, `service_info` free text.
- `SISEngineInfoReply.schema_version` is available but HTA relies on the Conan pin plus the encoding annotation instead.
- `tcn::sqe` contract has `MarkerKind` as a mirror (P2) and `kWireSchemaVersion = "0.10"` (P3), both need to move together with a 0.11.
