## 1. Goal and scope

- **No further break soon.** 0.11 is the one release in which every reshape happens. That includes the schema side of
  the planned ROS 2 robot integration (§5).
- **Scope rule (S-D1).**
  - **0.11.0** carries every reshape: removals, renames, moves, changed field types, extensibility, enum
    renumbering, and redesigns of existing types.
  - **New types, new union cases, new enumerators and new trailing `@optional` members** may follow in **0.11.x** as
    additive releases. This relies on E6 and E8 (§2) being normative in every codec from 0.11.0 on.
  - Additive items may still land in 0.11.0 when they are ready.
- **Release flow:** `0.11.0-rc1` for every consumer to regenerate against (#37), then `0.11.0` with a lockstep cut-over
  per site (#35 §9), with 0.10 kept installable for rollback. The work order is #39 §7.

## 2. Encoding (#35 D1, #36 D1, #39 §2)

Decided by all five teams (E-D1, E-D2, E-D3). The web controller verified the rules byte for byte against
fast-cdr 2.0.0.

| id | Decision |
|---|---|
| E1 | tcn types (`tcn_types`, `sqe_msgs`, `tcnart_msgs`, `pcpd_msgs`, `conversation_msgs`) use **XCDR2**. Every struct and union is declared `@appendable` explicitly. Writers use `Cdr(…, XCDRv2)` + `set_encoding_flag(DELIMIT_CDR2)` + `serialize_encapsulation()`; the encapsulation is `00 09`. |
| E2 | ROS 2 types are `@final` **in the IDL file** and are written as XCDR1 (`DDS_CDR`, `00 01`), byte-compatible with ROS 2. |
| E3 | The encoding belongs to the package family, not the topic. Readers switch on the encapsulation id. |
| E4 | conversation_msgs gets the encapsulation header (with #37 T16). |
| E5 | Decode into a fresh object. |
| E6 | Every enum starts with `…_UNKNOWN`/`…_NONE`. An unknown enumerator decodes as `…_UNKNOWN`. Every union switches on such an enum; an unknown case is skipped by its DHEADER and decodes as `…_UNKNOWN` with no member. **Normative.** |
| E7 | Small leaf structs are `@final`: `Vector2`, `Vector3`, `Quaternion`, `RigidTransform`, `SRPoint2D`, `builtin_interfaces/Time`. |
| E8 | A member missing from a shorter payload takes its default (0, `""`, empty, the first enumerator, an absent optional). So from 0.11.x on, new members are `@optional`, unless 0, `""` or empty is a true reading. **Normative.** |
| E9 | XTypes 1.3 encapsulation ids only (`00 06`–`00 0b`); no `@mutable`. |
| V1 | Annotation `application/cdr;{TYPE};tcn_schema=0.11`, mandatory, with the media type matched exactly (#35). |
| Toolchain | fast-dds-gen 3.0.0 / fast-cdr 2.0.0 stay; they support all of the above. `-de appendable` is passed explicitly. |

The pitfalls each hand-written codec must handle are in #39 §2.3. Hand-written codecs:
- SQE engine: Rust.
- Web controller: TypeScript (done).
- tcnart: Unity C#, the video and time-ref zero-copy encoders, and the mesh decoder.
- IVA: `tcn-wire` (Rust).
- HTA: C++ serde. HTA's Python goes through the C++ bindings.

Golden byte files are shared between tcn_schema `test/golden/` and the engine's `fixtures/wire`. They include an
evolution pair.

## 4. Deletions and removed fields (#39 §4)

- **Deleted files and types:**
  - **Group A:** `tcnart_msgs/rpc/SpatialRelations.idl`, `Logging.idl`, `pcpd_msgs/Instance.idl`, unused structs and enums.
  - **XA7:** `Pose6DMapMessage`, `RigidTransformMap(Item)`. Decided by the SQE.
  - **Group B:** `device_hl2_msgs`, `device_orbbec_msgs`, `GenericManager.idl`, `AudioStream.idl`,
    `XRInput.idl`/`XRRuntime.idl`, `CameraInfoMessage`, and the scalar request/reply pairs. These were used only by
    the deprecated tcnart v2.
  - Custom IDL files go from 43 to 27, before the reorganisation splits files (§3).
- **Kept:**
  - `ImuMessage`: no HTA app publishes it yet. The conversion from the Tobii glasses recordings exists, but the replay
    publisher is still open. It is kept because sensor fusion with the Tobii data (IMU, gaze, head pose) is planned
    soon (HTA, #38 §4; this corrects HTA's earlier reason).
  - `TimeRef`: adopted as the wire format, appendable (X-D2, tcnart, #37 T11).
  - `HumanPose`: kept and redesigned (§7).
- **Fields nobody writes are removed (F-D1).** The list is #39 §4.5 (F1–F5); the evidence is the field appendix.
  - **Readers to fix:** every team accepted its fix list in #39 §6. The web controller has done its fixes (branch
    `srg-dead-fields`).
  - **`SISGlobalTarget.custom_data`:** removed. No site uses it (camp, capture01 and narvis checked).
  - **`DeviceContextReply.is_valid`:** removed. Readers gate on the reply's `status` instead, as tcnart (Unity, Unreal)
    and the web controller already do. Calibration validity and revision come with #38 A4.
  - **Kept constants:** the exceptions in #39 §4.5, among them `SRNode.active`, which the engine honours (SQE).
  - **`EyeTrackingMessage.scene_point` (with its valid bit) and `gaze_space` (with `XRGazeSpaceType`): kept, as
    `@optional`.** This overrides #39 F2.
    - They are constant in tcnart's live producer, but HTA's recorded Tobii Pro Glasses 2 samples carry a real scene
      point and gaze space `View`.
    - HTA wants every measurement of the ATLAS dataset to stay usable and streamable (HTA, #38 §4; in line with #37
      T19).
    - tcnart's producer leaves them absent instead of writing (0,0) and `LOCAL`.
  - **Field appendix:** HTA checked all 101 HTA claims (#38 §4): 78 correct, 13 with only drifted line numbers, and 10
    to correct.
    - The corrections are listed in #38 §4 and change no other decision.
    - The main one: `listen.cpp:119` does not read `PersonTrackingMessage.header.frame_id`, so HTA has no reader of
      that field.
- **Engine bugs found by the review, fixed in engine B98 on 0.10.x** (engine PR #57, in review; deployment is
  announced on #39, when `op/info` reports `protocol_break >= 98`):
  - `display_name`/`description` of nodes and edges are stored and read back (F-D2). Graph-level ones are removed in 0.11 (F-D3, §9).
  - Untracked targets are dropped on ingest (`is_tracked`).
  - Projection edges read back as `SRG_EDGE_PROJECTION` with their stored intrinsics. Before B98, graph reads looked
    only at the pose rows, so every projection edge (HTA's eight `rig_cameraNN_*_image` edges included) read back as
    `STATIC_UNCALIBRATED` with an identity pose. Routing was never affected.

### HumanPose (#39 XC2, #37 T18, #38 A6)

Kept in 0.11.0 and redesigned as the **shared person stream**. Producers: HTA's pose tracker, and tcnart apps tracking
their own user. Consumers: tcnart avatars, the web controller, agents. `PersonTrackingMessage` stays HTA's
tracker-level output.

**Agreed by tcnart and HTA:**
- one `JointSet` table (`COCO17`, `HALPE26`, `TCN_LITE`, `TCN_BODY`; SMPL layouts with SMPL);
- `@optional` per-joint rotations;
- `@optional SmplParams` (tcnart's SMPL use behind a build option);
- the frame as a domain id / `SRFrameRef`, the clock as `ClockDomain`;
- `PersonState { UNKNOWN, TRACKED, COASTING, LOST }`;
- a latched shape message.

**HTA's four changes, accepted by tcnart (#38 comment 7218842696):**
1. Identity is a stable person id per producer, plus an optional `member` client id.
2. Keep per-joint confidence, `JointSource`, optional `source_ids`, and several persons per message.
3. The shape message is keyed by person and carries the joint set with a version, bone lengths, SMPL betas, model and
   gender.
4. The rotation convention is stated: rest-pose-relative in the stream's frame; SMPL pose stays SMPL's parent-relative
   axis-angle.

**Added by tcnart:**
- Each joint-set entry defines its **rest pose and axes**, not only joint order and bones, so "relative to the rest
  pose" is unambiguous for every consumer.
- Conversions between rest-pose-relative and parent-relative rotations, or between joint sets, live in the client
  libraries and never on the wire.

**Settled design (tcnart and HTA):** `docs/2026-11-27-0.11-humanpose-draft.md` on #37 (commit a17bced). HTA's answers
are on #38 (comment 7219084244), and tcnart folded them in (#38 comment 7219118307). The draft is the reference for
the IDL work. Its main points:
- **Messages:**
  - `HumanPoseMessage`: one per capture group, with a `StreamHeader` (whose `group_id` matches the PersonTracking
    group), a joint set with a version, and up to 32 persons;
  - a latched `HumanShapeMessage`, keyed by person;
  - a `PersonStreamInfo` for the descriptor's person case: `up`, `coast_limit_s`, `reid_window_s`, smoothing.
  - `PersonTrackingMessage` takes the same `JointSet` enum. Its `up` and `world_frame` move into `StreamHeader` and
    `PersonStreamInfo`.
- **Joint sets:**
  - one machine-readable table in tcn_schema, from which the enum, the C++/C# arrays and the docs are generated
    (it replaces `JointSets.md`);
  - **the table is complete for 0.11:** seven sets in `docs/2026-11-27-0.11-joint-sets-draft.{md,yaml}` on #37
    (commits d80df91, a5af508, 3e4a85d):
    - `COCO17`, `HALPE26` (HTA's rows);
    - `TCN_LITE` (7) and `TCN_BODY` (20 = today's `tcnart_body_v1`, which is retired explicitly);
    - `SMPL_24`, `SMPLH_52` (added for HTA's AMASS-trained prior) and `SMPLX_55`, as orders for `SmplParams.pose`
      only;
  - **HTA's format extension is adopted:** `kind: positions` sets (no parents, no rest pose, measured segments, cycles
    allowed), a `root: {midpoint: [a, b]}` for roots that are not joints, and `extends` as a prefix (a COCO17 reader
    reads HALPE26);
  - **SMPL verification:**
    - `SMPLH_52` is fully verified (the model file's `kintree_table`, plus the `smplx` package's names);
    - `SMPLX_55`'s names and order are verified, but its parents are "per the documentation, unverified";
    - `SMPL_24`'s joints 0–21 are verified, but joints 22–23 are "unverified";
    - whoever next has the SMPL/SMPL-X model files closes this with one line. It does not block 0.11;
  - consumers refuse an unknown (set, version) pair.
- **Defaults for now:** HTA publishes `HALPE26`/`COCO17` positions only. `TCN_BODY` with rotations follows HTA's
  rotation model; until then, conversion for avatars is in tcnart's library.
- **Life cycle:** `COASTING` lasts up to `coast_limit_s`. `LOST` is sent once, after `reid_window_s`, and is final.
- **Shape:** `bone_lengths` is NaN while not frozen.
- **One person, two producers:** de-duplicated by `member`. HTA leaves `member` empty until it links persons to
  headset users.
- **Up axis:** `up` is a stream property until #38 A9 lets the frame state its axes; then it is deprecated.

**HumanPose is settled.** The draft and the joint-set table on #37 are the design. Where they differ from the rules
above, the schema applies these points when it writes the IDL (decided here, so no further round is needed):
1. `SRFrameRef` is `tcn_types::SRFrameRef`, not `sqe_msgs::` (O-D1).
2. `SmplGender` starts with `SMPL_GENDER_UNKNOWN` (E6), followed by `NEUTRAL`, `FEMALE`, `MALE`. In the draft,
   `NEUTRAL` was ordinal 0.
3. `PersonStreamInfo.smoothing` becomes an enum `PersonSmoothing { UNKNOWN, OFF, ONE_EURO }`, appendable, instead of
   a free string (as #37 T14 does for pcpd). Filter parameters stay in the stream's properties.
4. `HumanShape.bone_lengths` keeps NaN for a bone that is not frozen yet. This is a deliberate per-element marker in a
   fixed-order sequence, which an `@optional` cannot express per element. It is documented in the table document,
   as HTA asked.

`@appendable` on enums, as the draft uses it, was checked: fast-dds-gen 3.0.0 accepts it.

**Hand-over:** tcnart and HTA hand the draft IDL and the joint-set table to the schema owner for `0.11.0-rc1`. The
table's YAML lands in tcn_schema as the source for the generated enum, arrays and docs.
