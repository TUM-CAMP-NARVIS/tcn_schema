## 1. Goal and scope

- **No further break soon.** 0.11 is the one release in which every reshape happens. That includes the schema side of
  the planned ROS 2 robot integration (§5).
- **Scope rule (S-D1).**
  - **0.11.0** carries every reshape: removals, renames, moves, changed field types, extensibility, enum
    renumbering, and redesigns of existing types.
  - **New types, new union cases, new enumerators and new trailing `@optional` members** may follow in **0.11.x** as
    additive releases. This relies on E6 and E8 (§2) being normative in every codec from 0.11.0 on.
  - Additive items may still land in 0.11.0 when they are ready.
- **Release flow:** `0.11.0-rc1` for every consumer to regenerate against (#37), then `0.11.0` with a lockstep cut-over
  per site (#35 §9), with 0.10 kept installable for rollback. The work order is #39 §7.

## 2. Encoding (#35 D1, #36 D1, #39 §2)

Decided by all five teams (E-D1, E-D2, E-D3). The web controller verified the rules byte for byte against
fast-cdr 2.0.0.

| id | Decision |
|---|---|
| E1 | tcn types (`tcn_types`, `sqe_msgs`, `tcnart_msgs`, `pcpd_msgs`, `conversation_msgs`) use **XCDR2**. Every struct and union is declared `@appendable` explicitly. Writers use `Cdr(…, XCDRv2)` + `set_encoding_flag(DELIMIT_CDR2)` + `serialize_encapsulation()`; the encapsulation is `00 09`. |
| E2 | ROS 2 types are `@final` **in the IDL file** and are written as XCDR1 (`DDS_CDR`, `00 01`), byte-compatible with ROS 2. |
| E3 | The encoding belongs to the package family, not the topic. Readers switch on the encapsulation id. |
| E4 | conversation_msgs gets the encapsulation header (with #37 T16). |
| E5 | Decode into a fresh object. |
| E6 | Every enum starts with `…_UNKNOWN`/`…_NONE`. An unknown enumerator decodes as `…_UNKNOWN`. Every union switches on such an enum; an unknown case is skipped by its DHEADER and decodes as `…_UNKNOWN` with no member. **Normative.** |
| E7 | Small leaf structs are `@final`: `Vector2`, `Vector3`, `Quaternion`, `RigidTransform`, `SRPoint2D`, `builtin_interfaces/Time`. |
| E8 | A member missing from a shorter payload takes its default (0, `""`, empty, the first enumerator, an absent optional). So from 0.11.x on, new members are `@optional`, unless 0, `""` or empty is a true reading. **Normative.** |
| E9 | XTypes 1.3 encapsulation ids only (`00 06`–`00 0b`); no `@mutable`. |
| V1 | Annotation `application/cdr;{TYPE};tcn_schema=0.11`, mandatory, with the media type matched exactly (#35). |
| Toolchain | fast-dds-gen 3.0.0 / fast-cdr 2.0.0 stay; they support all of the above. `-de appendable` is passed explicitly. |

The pitfalls each hand-written codec must handle are in #39 §2.3. Hand-written codecs:
- SQE engine: Rust.
- Web controller: TypeScript (done).
- tcnart: Unity C#, the video and time-ref zero-copy encoders, and the mesh decoder.
- IVA: `tcn-wire` (Rust).
- HTA: C++ serde. HTA's Python goes through the C++ bindings.

Golden byte files are shared between tcn_schema `test/golden/` and the engine's `fixtures/wire`. They include an
evolution pair.

## 4. Deletions and removed fields (#39 §4)

- **Deleted files and types:**
  - **Group A:** `tcnart_msgs/rpc/SpatialRelations.idl`, `Logging.idl`, `pcpd_msgs/Instance.idl`, unused structs and enums.
  - **XA7:** `Pose6DMapMessage`, `RigidTransformMap(Item)`. Decided by the SQE.
  - **Group B:** `device_hl2_msgs`, `device_orbbec_msgs`, `GenericManager.idl`, `AudioStream.idl`,
    `XRInput.idl`/`XRRuntime.idl`, `CameraInfoMessage`, and the scalar request/reply pairs. These were used only by
    the deprecated tcnart v2.
  - Custom IDL files go from 43 to 27, before the reorganisation splits files (§3).
- **Kept:**
  - `ImuMessage`: HTA's Tobii replay publishes it.
  - `TimeRef`: adopted as the wire format, appendable (X-D2, tcnart, #37 T11).
  - `HumanPose`: kept and redesigned (§7).
- **Fields nobody writes are removed (F-D1).** The list is #39 §4.5 (F1–F5); the evidence is the field appendix.
  - **Readers to fix:** every team accepted its fix list in #39 §6. The web controller has done its fixes (branch
    `srg-dead-fields`).
  - **`SISGlobalTarget.custom_data`:** removed. No site uses it (camp, capture01 and narvis checked).
  - **`DeviceContextReply.is_valid`:** removed. Readers gate on the reply's `status` instead (tcnart; web
    controller to confirm, §9). Calibration validity and revision come with #38 A4.
  - **Kept constants:** the exceptions in #39 §4.5, among them `SRNode.active`, which the engine honours (SQE).
- **Engine bugs found by the field scan, fixed in engine B98 on 0.10.x:**
  - `display_name`/`description` are stored (F-D2).
  - Untracked targets are dropped on ingest (`is_tracked`).

### HumanPose (#39 XC2, #37 T18, #38 A6)

Kept in 0.11.0 and redesigned as the **shared person stream**. Producers: HTA's pose tracker, and tcnart apps tracking
their own user. Consumers: tcnart avatars, the web controller, agents. `PersonTrackingMessage` stays HTA's
tracker-level output.

**Agreed by tcnart and HTA:**
- one `JointSet` table (`COCO17`, `HALPE26`, `TCN_LITE`, `TCN_BODY`; SMPL layouts with SMPL);
- `@optional` per-joint rotations;
- `@optional SmplParams` (tcnart's SMPL use behind a build option);
- the frame as a domain id / `SRFrameRef`, the clock as `ClockDomain`;
- `PersonState { UNKNOWN, TRACKED, COASTING, LOST }`;
- a latched shape message.

**HTA's four changes, pending tcnart's acceptance (§9):**
1. Identity is a stable person id per producer, plus an optional `member` client id.
2. Keep per-joint confidence, `JointSource`, optional `source_ids`, and several persons per message.
3. The shape message is keyed by person and carries the joint set with a version, bone lengths, SMPL betas, model and
   gender.
4. The rotation convention is stated: rest-pose-relative in the stream's frame; SMPL pose stays SMPL's parent-relative
   axis-angle.

## 8. Cross-proposal conflicts: resolved

| Conflict | Resolution | Agreed by |
|---|---|---|
| Clock domain (#37 T10 vs #38 A1), C-D1 | `ClockDomain { string id; ClockKind kind; }` in `tcn_types`. `id` follows T10's alphabet, with `""` = the deployment clock. Equality is on `id` alone; `kind` is informational; the display form is `id`. Used in descriptors, `StreamHeader` and SQE outputs. The descriptor stays authoritative for routing. | SQE, tcnart, HTA; web either |
| Descriptor target list (#37 T7 vs #38 A2) | Explicit ids: `sequence<SISTargetInfo { uint32 id; string name; SISTargetKind kind; }>`, in `tcn_types`. | SQE, tcnart, HTA |
| `ErrorCode` vs Windows macros (#36 L3 vs #37 T16) | `ERROR_CODE_*` in L3. | IVA, tcnart |
| Pixel semantics (#37 T9 vs #38 A2) | A2's semantics enum; T9 withdrawn; `DEPTH_F32` added. | tcnart, HTA |
| Intrinsics (#35 E2, #37 T4/T8, #38 A3) | One `CameraIntrinsics`; E2's distortion enum; nominal in the descriptor, optional per frame. | tcnart, HTA |
| Scope beyond #35 §8 | The scope rule (§1). `SRFrameRef` and `SISTargetInfo` move to `tcn_types`, so stream types do not depend on `sqe_msgs`. | SQE, tcnart |
