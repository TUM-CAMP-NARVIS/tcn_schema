# tcn_schema 0.11: type usage by the five consumers (appendix)

2026-11-27. Companion to `2026-11-27-0.11-schema-housekeeping-proposal.md`, §1 and §4. One entry per IDL file,
with every top-level type (struct, enum, union) and its verdict. Each verdict gives one evidence location per consumer.
Please check the entries for your consumer and comment on the PR where an entry is wrong.

**Excluded from the scan:**
- artekmed and every other checkout, because they are deprecated;
- tcnart's vendored IDL snapshot `v3/third_party/tcn_schema_idl`;
- IVA's pinned `idl/` copy and `third_party/`;
- the web controller's uncommitted changes in `packages/cdr`.

**Verdicts:**
- **KEEP:** hand-written code constructs, encodes, decodes, publishes or subscribes the type. Wire type-name strings
  also count.
- **MEMBER-ONLY:** the type is used only as a field of a KEEP type.
- **V2-ONLY:** only tcnart's legacy v2 code uses the type.
- **GENERATED-ONLY:** the type exists only in generated code. tcnart's idlgen emits C#/JSON for whole packages:
  `builtin_interfaces;std_msgs;geometry_msgs;tf2_msgs;tcnart_msgs;pcpd_msgs` by default
  (`v3/cmake/TcnartV3Options.cmake:26`); other packages are opt-in.
- **UNUSED:** the type is referenced nowhere.

The letters after a type name say who uses it.

**Method:**
- KEEP verdicts that rested only on a bare type name were checked by hand. That removed 17 false positives, for
  example Unity's own `Vector4`/`Matrix4x4`, IVA's `ParameterValueType::Int32` and `tcn.PointCloud`.
- Branches that are not merged were not scanned. tcnart `v3/unreal` is the known one.
- Types named only at runtime, such as tcnart's `TCNART_V3_HOST_TYPES` opt-ins in deployment configs, cannot be seen
  by this scan.
- An `I` can be weaker than it looks. IVA keeps a Rust definition of every conversation_msgs type
  (`crates/common-types`, `crates/tcn-wire`), so an `I` alone may mean "IVA defines it" rather than "IVA sends it".
  #36 says that `SessionConfigUpdate` and `SttRequest` are never published.
