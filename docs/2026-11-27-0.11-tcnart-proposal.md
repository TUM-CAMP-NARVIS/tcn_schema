# Proposal: tcn_schema 0.11, tcnart's additions and answers

2026-11-27. Status: **proposal, for review.** From tcnart v3 (branch `v3/sqe-b94`, tcn_schema 0.10.7, sqe_client_cpp
0.6.3).

This proposal complements PR #35, "the SQE wire cleanup"
(`docs/2026-11-27-0.11-sqe-wire-cleanup-proposal.md`). It does three things:
1. answers #35's open decisions and checks from tcnart's side (§1);
2. adds SQE items that tcnart's integration ran into (§2);
3. proposes changes to the **non-SQE** types tcnart publishes and reads, which #35 does not cover (§3).

The full inventory of what tcnart uses is in `docs/2026-11-27-tcnart-schema-inventory.md`, organised by IDL file,
type, role, fields and files. Item ids (`T1` and so on) are for the review discussion. #35's ids (`N2`, `R5`, `D1`, …)
are referred to as written there.

## 1. Answers to #35

- **D1 (XCDR2 `@appendable`): yes, strongly.** tcnart pays for every additive field three times today:
  - the C++ codec;
  - the generated Unity C# codec (`TcnartCdr`, idlgen);
  - hand-encoded zero-copy paths (VideoStreamMessage, TimeRef; see T5).

  Its own C ABI already versions structs by `struct_size` for the same reason. Appendable types would make a
  0.11 → 0.12 addition a non-event for tcnart.
- **D2 (`SRFrameRef` as a struct with a scope discriminator): yes.** One request on top: the contract library should
  define the **canonical text form** of a frame ref (parse and format), and every tool should use it. Configs, UIs,
  CLIs and logs need text, and today every client invents its own: tcnart writes `node`, `<client>/<node>` and
  `@<domain>::<name>`; HTA writes something else; `sqe-calibrate` has its own form. Proposed:
  `local:<fragment>/<name>`, `global:<name>` and `domain:<domain>/<name>`, plus the selector `…:::*` written as
  `…[instances]`, with round-trip tests in the library.
- **D3 (vocabulary): node/edge.** tcnart's code, docs and C ABI already say node and edge, matching the types.
- **D4 (`NOT_IN_SCOPE`): capabilities first.** tcnart reads `op/info` `protocol_break` once per engine epoch today
  (inventory §5.22). A join reply that carries `protocol_break` and `capabilities` (R5) removes that extra query.
  - A client outside every scope can still only time out. That is acceptable if `op/info` (or the unscoped
    `sqe/{engine}/info`) also lists `client_scope`: a client can then say "no engine serves `<id>`" instead of
    "no engine".
  - We have no strong need for the catch-all key.
- **D5 (delete marker discovery from poses):** fine for tcnart. It announces every marker it tracks.
- **G2 (`Target.quality`):** tcnart writes `quality = 1.0` and `is_tracked`, and no tcnart reader uses `quality`.
  Drop it, or define it precisely (0 to 1, the probability that the pose is within its covariance) and make it
  optional (P3). Keep `is_tracked`.
- **§6 "check tcnart before deleting"** the legacy `rpc/SpatialRelations.idl` types (`SRNodeRef`, `SRGraphPublish*`,
  `SRGraphQuery*`): **tcnart does not use them.** It excludes them from its generator, because
  `rpc/SpatialRelations.h` ships as a copy of `msg/SpatialRelations.h` (a packaging bug). Delete them.
- **S2 (`target_origin`):** tcnart always writes identity. Removing it is fine.
- **N5 (structured materialization):** yes. tcnart today encodes marker refs as names
  (`@marker/<kind>/<system>/<id>`) and resolves them through the registry before every join. Two requests:
  - a **client call** in sqe_client_cpp, "resolve marker (type, system, domain, id) to a frame ref", so clients stop
    composing names;
  - a guarantee that a marker announced by id (H5) and a registry target with that alias meet on one node. Engine
    #49 does this today.

## 2. SQE additions

| id | today (tcnart's view) | 0.11 |
|---|---|---|
| T1 | `SRCalibration.method` is free text that identifies the calibrating tool ("tcnart camera mount (config)", "tcnart sqe.space_anchors (surveyed)", "tcnart marker registration (…)"). `residual = -1` means "not measured". | **`SRProvenance { string tool; string method; optional double residual; optional SRCovariance6 covariance; Time computed_at; uint32 samples; }`**. `tool` is a stable id (`tcnart.camera_mount`, `sqe-calibrate`, …). UIs and agents can then filter by tool without parsing text. No sentinel (P3). |
| T2 | "Calibration needed" is inferred from `blocked_by[].temporal_type == STATIC_UNCALIBRATED`. Calibration tools find the edges to calibrate by convention, a `SIS_GQ_SEARCH` on STATIC_UNCALIBRATED. | Covered by R3 `SISParkReason.UNCALIBRATED` for the stream. Additionally, an edge field **`calibration_wanted`** (or `SREdgeTiming.STATIC_UNCALIBRATED` defined as exactly that), so `sqe-calibrate` and an agent can list "what needs calibrating" with a filter (G3). |
| T3 | Every tcnart node declares `coord = OpenCV`, and tcnart converts before publishing. | Keep per-node `coord`, but give it an engine-wide default (OpenCV) and make it optional (P3). Most clients then send nothing. |
| T4 | Projection edges (B61, B96) carry pinhole intrinsics in pixels. tcnart's design 2 publishes **eye frustums** for headsets (from the XR views: an asymmetric FOV given as four angles, no pixels) and projection edges for every camera. | `SRIntrinsics` gets a **union by model**: `PINHOLE_PIXELS` (today's fx, fy, cx, cy, size, distortion: E2) and `FOV_ANGLES` (left, right, up, down in radians, plus near and far). A render camera's frustum is then stated without inventing an image size. Agents can reason about visibility ("is the target in the user's view") from the graph. |
| T5 | The relation sample (B93) is answered `NO_ROUTE` or `UNKNOWN_FRAME` for an out-of-scope frame, and `REJECTED` only for malformed requests. tcnart's C ABI and docs explain each case. | R1 and R2 cover this. Please keep a **sample reply** with the engine identity (R2) and add `capabilities` to `op/info`, so a host can report "engine B9x, no `sample`" up front. |
| T6 | Edge names must be identifiers, so tcnart builds them from bare names (`xr_home_world`). | With N3 (endpoints as refs), state that edge names are **opaque and unique per fragment**, and that the engine never derives meaning from them. |

## 3. Non-SQE types tcnart publishes and reads

| id | type(s) | today | 0.11 |
|---|---|---|---|
| T7 | `StreamDescriptorMessage.buffer_info.properties` | A name/int side channel carries structured data. For XR it holds the target ids (`target/<name>` = id) and the eye views' FOV in microradians (`view/fov_{left,right,up,down}_urad`), plus `eye/source` and `eye/pupils`. For video it holds the H.26x codec configuration (`h26x_codec_data` with a `user_data` blob). | Typed fields in #35's S1 union. **Tracker case:** `sequence<SISTargetInfo { uint32 id; string name; SISTargetKind kind; }>`. **XR case:** `sequence<XRViewInfo { string name; SRIntrinsics fov /*FOV_ANGLES, T4*/; RigidTransform eye_in_head; }>`. **Video case:** `sequence<octet> codec_config`. Properties stay for vendor extensions only. |
| T8 | `VideoStreamMessage` | It carries fixed `camera_radial_distortion[3]` and `camera_tangential_distortion[2]` next to the focal length and principal point. tcnart hand-encodes it for zero-copy. | Use the **one intrinsics type** (`SRIntrinsics` / `CameraModel`, E2's distortion enum) for the per-frame camera. Keep the image payload last and appendable, so zero-copy encoders keep a fixed prefix. |
| T9 | `SensorType` / `VideoPixelFormat` | A mono8 mask is sent as `SENSOR_TYPE_NONE`. Depth is inferred from the stream name "depth". Float depth is sent as MONO16. | Add **`SENSOR_TYPE_VIDEO_MASK`**, use `VIDEO_DEPTH` explicitly, and add **`VIDEO_PIXEL_FORMAT_DEPTH_F32`**. Put `depth_units_per_meter` in the descriptor (today it is only in pcpd's `CameraSensor`). |
| T10 | Clock domains | `StreamDescriptorMessage.clock_domain` is a free string. tcnart hashes it to a numeric id (FNV); `""` means the deployment clock. | Keep the string, but define it in one place: its alphabet, `""` = deployment, and the same field on SQE output (`clock_domain` is already in the sample reply). |
| T11 | `TimeRefRequest/Reply` | They exist in the IDL but are unused: tcnart hand-codes a 28-byte reply on `tcn/time/ref/<name>` that matches no generated codec. | Either make the IDL type **the** wire format (and appendable), or delete it and document the 28-byte layout. tcnart prefers the IDL type. |
| T12 | Mesh streams | The MeshStream v2 binary ("TMS2", `tcn::MeshStreamV2Message`) is outside the IDL. One sender names the format-A type `tcnart_msgs::msg::MeshBitstreamMessage` although it lives in `pcpd_msgs`. | Bring **`MeshStreamV2Message` into the IDL**, as a header plus a payload blob, so its type name is registered. Fix or alias the format-A type name. |
| T13 | `Requests.idl` parameters | PVT_STRUCT is unsupported. uint32 and uint64 travel as PVT_INT64 on the old verbs. Enum parameters are PVT_STRING with `enum_entries`. `ParameterSetStatus` has a "2 reserved" ordinal that clients hard-code. | Add **`PVT_UINT64`** and **`PVT_ENUM`** (carrying the entry name and value), define PVT_STRUCT or delete it, and renumber `ParameterSetStatus` without the gap (the break allows it). |
| T14 | `pcpd_msgs` service types | `StreamAnnouncement.role` ("data", "descriptor", "state") and `.mode` ("stream", "latched") are strings. `ProcessInfo.started_at` is an ISO-8601 string. `GraphReply.graph_json` is a JSON document in a string. | Enums for `role` and `mode`, and `builtin_interfaces/Time` for `started_at`. `graph_json` may stay, but document its schema next to the IDL. |
| T15 | `TcnartPresenceMessage` | `header.frame_id` carries the RPC root. `ServiceInfo.service_info` is a constant type-name string. | An explicit **`rpc_root`** field. `service_info` becomes `service_type` (the enum pcpd already has) or is documented. |
| T16 | `conversation_msgs` | Plain CDR with no encapsulation header and no `tcn_schema=` annotation. The enumerators `ERROR_TIMEOUT` and `ERROR_CANCELLED` clash with Windows macros (tcnart `#undef`s around the include). | Same encoding rules as everything else (V1). **Prefix the enumerators** (`CONV_ERROR_*`, or scoped enums in the generator). |
| T17 | Generated enums in hosts | Unreal hard-codes `CameraModelType` and `ParameterSetStatus` ordinals by name text. The contract library mirrors `MarkerType` as `MarkerKind`, pinned by static_asserts. | Supports #35 §6 (generate the mirrors). Also ship a **JSON or IDL-derived enum table** that host generators (C#, Unreal) consume, so no host keeps ordinals by hand. |
| T18 | `HumanPose` / `PersonTracking` | The IDL exists in 0.10.7, with no tcnart user yet. tcnart's next slice (full-body avatars) will use it. | Review before 0.11 locks. Needs per-joint confidence, a skeleton id and version (an enum or a registry key), and the clock domain and frame named as for poses. It should be designed as appendable from day one. |
| T19 | `TargetTrackingMessage` for XR | An untracked target is sent with an identity pose and `is_tracked = false`. Gaze is a target (`XR_POSE_GAZE`) derived from eye data. `EyeTrackingMessage.scene_point` is never computed. | Make the untracked pose **absent** (an optional pose, P3), not identity. Leave `scene_point` out until a producer exists, or make it optional. |

## 4. Rollout notes for tcnart

- tcnart pins tcn_schema exactly and vendors an IDL snapshot. Its generator (idlgen) builds whole packages, so any
  construct idlgen cannot map breaks tcnart's configure step. Please give us the 0.11 IDL **as a release candidate**
  (e.g. `0.11.0-rc1`) before the engine cut-over. tcnart then regenerates C++, C# and JSON and reports gaps.
- If D1 (XCDR2) is adopted, tcnart's Unity CDR codec and two zero-copy encoders (video, time ref) must learn DHEADERs.
  The work is about one task. Field order still matters for the zero-copy prefix (T8).
- tcnart's C ABI exposes no IDL structs directly, and SQE results are flat C structs. So the host ABI stays stable
  across 0.11, apart from the typed publish/subscribe of user-chosen types, which follows the regenerated C#.
