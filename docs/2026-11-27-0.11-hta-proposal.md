# Proposal: tcn_schema 0.11, from HTA (holoscan-tcn-applications)

A proposal document with no IDL change, for the planned 0.11 break. It complements #35 (the SQE wire cleanup) and #36
(conversation_msgs): §1 answers #35's questions from HTA's side, §2 adds what HTA needs beyond the SQE (media streams,
calibration, time, poses, persons), §3 ranks it. The inventory of every tcn_schema element HTA uses, with code
locations and the workarounds behind each item here (P1-P19), is `docs/2026-11-27-0.11-hta-inventory.md`.

HTA's use in one paragraph: HTA publishes and subscribes video, depth and IR streams (`VideoStreamMessage`,
`StreamDescriptorMessage`), point clouds and surfels (`sensor_msgs::PointCloud2`), meshes (`pcpd_msgs::MeshBitstreamMessage`
and a v2 container inside it), poses (`TargetTrackingMessage` / `Pose6DMapMessage`), persons (`PersonTrackingMessage`),
camera calibrations (`pcpd_msgs::CameraSensor` and HTA's own FlatBuffers mirror), the parameter service
(`tcnart_msgs::rpc` parameter types), presence, and the whole SQE client surface (`SpatialRelations.idl`, the `tcn::sqe`
contract library, sqe_client_cpp). It does not use conversation_msgs.

## 1. On #35 (the SQE wire cleanup)

### Items HTA needs most (from design 81 and engines B94-B97)

| #35 item | why HTA wants it (inventory) |
|---|---|
| N1, N2, N3 (`SRNode.domain`, `SRFrameRef`) | HTA declares cameras, devices and targets as domain nodes; the `@{domain}::{name}` id is parsed in C++, Python and the web controller, with role guessing by name regex (P1). |
| N5, N6, H5 (structured materialization, `marker_domain`, announce by id) | `marker_system` carries family, dictionary, a `replay.` prefix and `@{space}` split at the last `@` (P2); `cfg/marker` tokens carry node names (P14). |
| R5 (capabilities in the join reply) | HTA gates features on `op/info` `protocol_break` (95 domain templates, 96 rational lens, 97 marker spaces) with a separate query per engine epoch, because an engine that cannot read a model refuses the **whole join**, rig extrinsics included (P3). |
| E2 (distortion enum, `metric_radius`) | Every Azure Kinect is OpenCV's rational model; the IDL named an unimplemented fisheye (P4). See also A3 below: one intrinsics struct for the whole schema. |
| S1 (typed descriptor per sensor kind) | The flat descriptor is HTA's largest pain; A2 below extends S1 to the media kinds. |
| S2 (`target_origin` removed) | HTA writes identity, never reads it. |

### Checks #35 asked for

- **Delete (§6):** HTA uses none of `SRNodeRef`, `SRGraphPublish*`, `SRGraphQuery*`, `SRNodeTemplate`, `HumanPoseMessage`,
  `TimeRef*`, `SRCalibration` (grep of HTA main, 2026-11-27). `target_origin`: written as identity only.
- **G2 (`Target.quality`):** HTA writes a constant `1` and never reads it: drop it, or define it (e.g. as a probability).
- **D1 (XCDR2 `@appendable`): yes.** The 0.10.7 enum value `SRG_SCOPE_DOMAIN` broke the web controller's decoder for every
  HTA fragment (it knew two scopes). With appendable types, please also state a rule for **unknown enum ordinals**
  (decode, report as `UNKNOWN`) and make every enum's first value an explicit `UNKNOWN` or `NONE`.
- **D2:** a struct with a `scope` discriminator is fine for HTA.
- **D4:** capabilities alone are enough for HTA; we would replace our three protocol-break gates with capability names.
- **D5:** HTA announces markers (`cfg/marker`); no objection to deleting discovery from poses.
- **G1:** HTA's code and docs say node/edge for the graph and frame for references; either works if it is one each.

## 2. Additions from HTA

### A1. A common stream header: time, groups, clocks (P7, P8)

Today `std_msgs::Header` has an `int32` second, one stamp per message and a free `frame_id`; video and mesh streams
have no group id, so receivers regroup the four cameras of one capture by a time tolerance; the capture's group id
lives only in HTA's shared memory and is lost on Zenoh; device and host times are paired only in HTA's recordings.

Proposal: **`StreamHeader { int64 capture_time_ns; int64 device_time_ns (optional); uint64 sequence; uint64 group_id
(optional); ClockDomain clock; SRFrameRef frame; }`** first in every stream message (video, point cloud, mesh, pose,
persons). `ClockDomain { string id; ClockKind kind (HOST, DEVICE, PTP, ...); }` instead of the free `clock_domain`
string. `frame` replaces the overloaded `header.frame_id` (a camera frame, an SQE device node, `world`, `mosaic`).

### A2. Typed media descriptors (extends #35 S1; P5, P6)

`buffer_info.properties` is a bag for everything the descriptor cannot say: H.26x parameter sets (`h26x_codec_data`),
pose target names (`target/<name>` = id), the persons' properties (`joint_set`, `up`, `smoothing`, `rate_hz`, ...), mesh
capacities, and a magic `semantic_type`. `h26x_profile` doubles as the codec selector; IR and depth are both `L16`.

Proposal, per sensor kind in S1's union:
- **video / depth / IR:** `Codec` enum separate from the profile (`RAW`, `H264`, `H265`, `H264_LOSSLESS`, `JPEG_LS`,
  `ZDEPTH`, `NDQ`, ...), `bytes codec_data`, width, height, pixel format, a pixel **semantics** enum (`COLOR`, `DEPTH`,
  `IR`, `MASK`, ...), depth units per metre.
- **tracker:** as S1, plus `sequence<string> target_names` (index = target id).
- **persons:** typed fields for what is a property today (joint set, up vector, units, handedness, filter settings).
- **mesh:** a first-class mesh stream (capacities, encoding enum) instead of `MeshBitstreamMessage` with
  `vertex_size_bytes = 0` and a schema name that says `tcnart_msgs` for a `pcpd_msgs` type.
- **surfels:** a typed surfel layout (position, normal, radius, colour, class id, instance id) rather than
  `PointCloud2` field conventions.

### A3. One camera intrinsics struct (P4)

Intrinsics live in four places: `pcpd_msgs::CameraModel`, `SRIntrinsics`, `VideoStreamMessage` (`radial[3]`,
`tangential[2]`, unused), and HTA's FlatBuffers mirror of the ArteKMed calibration. Proposal: one
**`CameraIntrinsics`** (#35's E2 enum and `metric_radius`, a documented coefficient order per model, image size, `double`
throughout), used by `CameraSensor`, `SRIntrinsics` and the video descriptor (drop the video message's copy).

### A4. Calibrations with revision and provenance (P11, P12)

`CameraSensor` has no revision and no provenance, its poses use ArteKMed's OpenGL camera frame without saying so, and
`depth_units_per_meter` is missing. Live calibration changes travel as HTA JSON (`calibration/set`,
`calibration/changed {revision, cameras}`), and a tracking-ownership check as another JSON query.

Proposal: `CameraSensor` gains `uint32 revision`, a provenance struct (method, residual, computed time, source; the
same as `SRCalibration`, which then also gets used), a declared coordinate convention, and depth units. Typed RPC
messages: `CalibrationSetRequest/Reply`, `CalibrationChangedNotification { revision; cameras }`.

### A5. Poses (P9)

`TargetTrackingMessage` has no per-target stamp (HTA stamps the message with the earliest entry), names travel only in
the descriptor's property bag, and the covariance's frame and order are not stated (HTA permutes a 6x6 both ways).
Proposal: per-target `int64 stamp_ns`, the name in the descriptor (A2), the covariance's frame and order stated in the
IDL (with #35 E1's `SRCovariance6`).

### A6. Persons and skeletons (P10)

`joint_set` is a free string keyed into `JointSets.md`; rotations exist but nobody produces them; SMPL parameters have
no home. HTA's pose tracking reaches the SQE through N fixed `person_<k>` slot nodes because the engine cannot create
targets from a tracked list.
Proposal: a `JointSet` enum (or registry) in the IDL with the joint counts; optional **SMPL** fields per person
(`pose` axis-angles, `betas`, `root_orientation`, model id); and, for the engine (beyond 0.11's IDL): targets created
and retired from a tracked list stream, so persons need no fixed slots.

### A7. Descriptor revisions (P14)

A re-announced descriptor under the same key with a changed `marker_system` was ignored about one run in four (B97);
HTA now withdraws, waits for the engine, and re-announces. Proposal: `uint32 revision` (or an epoch) in every
descriptor, and a stated rule that the engine re-reads a descriptor whose revision changed. Complements #35 R6.

### A8. Wire typing and large payloads (P12, P13, P17)

- **One typing profile.** Today the type travels as an attachment (artekmed) or in the encoding (tcnart), and the
  engine's 13-byte pose attachment collided with the first. With #35 H3 removing that attachment: the type in the
  encoding only, and `WireType<T>` in the contract library for every message, not only the SQE and tracking ones.
- **`StreamAnnouncementReply`** lacks transport, host, endpoint, catalog and slots, which only its JSON form carries.
  Add them, and publish the canonical JSON mapping of the parameter types (with generated enums for Python).
- **Zero copy.** HTA writes the CDR prefix of `VideoStreamMessage` and `PointCloud2` itself and patches the length
  fields, to send a shared-memory frame without a copy. Proposal: the payload as the last member, documented as such
  (its offset computable from the header alone), or carried as a separate Zenoh attachment.

### A9. Node roles and coordinate systems (P15, P16)

The 5-value `SRNodeType` cannot say camera, image plane, tracker device, target, rig reference or marker, so HTA infers
roles from name patterns (`*_depth`, `*_color_image`, `world`). Proposal: an `SRNodeRole` enum (or extend the type), and
`CoordinateSystem` presets (OpenCV camera, OpenGL camera, ROS body, image plane) so a node states its axes instead of
every HTA node carrying OpenCV's.

## 3. Priorities for HTA

| priority | items |
|---|---|
| must have | #35 N1-N3, N5-N6, R5, E2, S1; A1 (group id, time), A2 (codec and semantics), A3 (one intrinsics) |
| should have | A4, A5, A7, #35 D1 with the unknown-ordinal rule |
| nice to have | A6 SMPL fields (engine-side dynamic targets later), A8, A9 |

HTA side of the rollout: the SQE link and naming code (design 81), the media publishers and subscribers, the recording
mirrors in `schemas/*.fbs` (field-for-field copies of several IDL types, inventory §1.8), and the Python dict builders.
HTA can take the lockstep on the cut-over day #35 §9 proposes.
