# The joint-set table for 0.11: file format and tcnart's rows (draft)

2026-11-27. Status: **draft**. It goes with `docs/2026-11-27-0.11-humanpose-draft.md` §4. The rows are in
`docs/2026-11-27-0.11-joint-sets-draft.yaml`:
- tcnart drafted `TCN_BODY`, `TCN_LITE`, `SMPL_24`, `SMPLX_55` and `SMPLH_52`;
- HTA drafted `COCO17` and `HALPE26` (#37, 2026-11-27), with a format extension for position-only sets, adopted below.

## 1. Why one file

Today the joint sets live in `tcnart_msgs/msg/JointSets.md`, a document that each consumer re-types into its own
arrays: tcnart's C++ and C#, HTA's C++ and Python, the web controller. One machine-readable table instead:
- generates the IDL enum `JointSet`;
- generates per-language constant arrays (names, parents, bones, rest directions);
- generates the docs page.

A joint set's order and rest pose can then never disagree between producer and consumer.

## 2. File format (`format: 1`)

YAML (JSON-compatible), one file in tcn_schema. Proposed path: `src/dds/custom/tcnart_msgs/msg/joint_sets.yaml`.

| key | meaning |
|---|---|
| `body_frame` | the canonical body frame B (right-handed; +x the person's left, +y up, +z forward) in which every rest pose is stated |
| `joint_sets[]` | one entry per set |
| `.id` | the enum name without its prefix (`TCN_BODY` → `JOINT_SET_TCN_BODY`) |
| `.ordinal` | the enum value: fixed, never reused |
| `.version` | `joint_set_version`; bumped on any change to joints, bones or the rest pose of this set |
| `.replaces` | retired string names (`tcnart_body_v1`), for readers of old data |
| `.kind` | `tree` (default: parents, rest pose, rotations) or `positions` (HTA: no parents, no rest pose, no rotations; `bones` are measured segments without `rest_dir`; the generator skips the tree checks) |
| `.root` | the root joint, or `{midpoint: [a, b]}` for a root that is not a joint |
| `.extends` | `positions` sets: the set's first joints and bones are another set's (a COCO17 reader reads a HALPE26 message by its prefix) |
| `.rest_pose` | `t_pose` (stated here through `bones[].rest_dir`), or `smpl`/`smplx` (the model's own, not stated: licensed data) |
| `.joints[]` | in wire order (index = position): `name`, `parent` (`null` for the root), optional `body` (the corresponding TCN_BODY joint), `source` (the usual JointSource), `note` |
| `.bones[]` | in `bone_lengths` order: `from` (parent joint), `to` (child joint), `rest_dir` (unit vector in B: the child's direction at rest). The bone's rotation is the rotation of `from`. |
| `.pose_excludes_root` | SMPL orders only: `SmplParams.pose` holds joints 1..N-1, and the root is `global_orient` |
| `.rotations` | which joints carry rotations, and where they come from (informational) |
| `.maps_from` / `.maps_to` | informational pointers for the client libraries' index maps; maps are code, not wire |
| `.verified` | how the row was checked (e.g. against a model file's kinematic tree) |
| shorthands | `{range, same_as}` reuses another set's joints; `{hand, parent, fingers, joints_per_finger}` expands to `<hand>_<finger><1..3>` chains. The generator expands both. |

**Rules the generator checks:**
- unique names within a set;
- `tree` sets: exactly one root;
- `tree` sets: every parent appears earlier in the list, every bone joins a parent to its child, and `rest_dir` is a
  unit vector;
- `positions` sets: every bone joins two joints of the set (cycles allowed), and `extends` is a prefix;
- each ordinal is used once across all sets;
- a set's `version` changes whenever its joints, bones or rest pose change (checked against the previous release's
  file).

**Consumers** refuse an unknown (`joint_set`, `joint_set_version`) pair loudly.

## 3. The rows

- **`COCO17`, `HALPE26` (HTA):** position-only (`kind: positions`). `HALPE26` extends `COCO17`. Both have the hip
  midpoint as root, and `HALPE26` maps to `TCN_BODY` as HTA's `maps_to` states.
- **`TCN_BODY` v1:**
  - Today's `tcnart_body_v1`, unchanged: 20 joints, 19 bones and the T-pose rest pose in B.
  - Pelvis, chest and head get rotations derived from positions; limb twist and feet have none until a source with
    rotations exists.
  - The string `tcnart_body_v1` is retired.
- **`TCN_LITE` v1:**
  - Seven joints: head, chest, pelvis, both hands (the wrist frames) and both controllers.
  - Chest and pelvis are derived, as tcnart's lightweight avatars do today.
  - Controllers are defaulted with confidence 0 when not held.
  - Only the two physical bones (pelvis→chest→head) have lengths; hands and controllers float.
  - Every joint names its `TCN_BODY` counterpart, so a consumer can show a lite user on a full-body rig.
- **`SMPL_24`, `SMPLX_55` and `SMPLH_52`:**
  - Joint names, parents and order only. These are the orders of `SmplParams.pose`, and nothing else uses them.
  - No rest pose or template is stated, because SMPL's are licensed model data.
  - SMPL-X's joints 0–21 equal SMPL's. Then come jaw and both eyes, and 15 joints per hand (index, middle, pinky,
    ring, thumb; 3 each, chained from the wrist).
  - `SMPLH_52` (HTA's request: AMASS and HTA's pose prior are SMPL+H) is SMPL's body 0–21, then 15 joints per
    hand; `pose` holds joints 1–51.
  - **Verification status:**
    - `SMPLH_52`: fully checked. The parents match the SMPL+H model file's `kintree_table` (tcnart), and the names and
      order match the `smplx` package's `SMPLH_JOINT_NAMES` (HTA).
    - `SMPLX_55`: the names and order match the `smplx` package's `JOINT_NAMES` (HTA; the package names the eyes
      `left_eye_smplhf` and `right_eye_smplhf`). The parents follow the documentation and are **unverified**.
    - `SMPL_24`: joints 0–21 are checked. Joints 22–23 (the hands) and their parents follow the documentation and are
      **unverified**.
    - Whoever next has the SMPL and SMPL-X model files closes this with `np.load(...)['kintree_table'][0]`. It does not
      block the table.
