# Proposal: tcn_schema 0.11 — `conversation_msgs` (the voice pipeline)

2026-11-27. Status: **proposal, for review.** Scope: `src/dds/custom/conversation_msgs/` (`msg/*.idl`,
`rpc/discovery.idl`). Companion to the SQE proposal (PR #35, `2026-11-27-0.11-sqe-wire-cleanup-proposal.md`), whose
rollout already says "the IVA change joins this release"; this is that change.

Sources:
- an audit of every field against its producers and consumers in the realtime conversational pipeline
  (`TUM-CAMP-NARVIS/realtime_conversational_pipeline`: app-server, orchestrator, STT/LLM/TTS services, voice and text
  clients, the observer) and tcnart v3 (`features/src/voice/voice_agent.cpp`, the Unity types);
- limits hit in recent pipeline work: confirmed barge-in and the wake word (pipeline PR #17), where the server cannot
  know when a reply has actually finished playing.

Item ids (`S3`, `T1`, …) are for the review discussion. Each item says whether it **breaks** the wire or is
**additive** (could ship in a 0.10.x micro release on its own).

## 0. Principles

The SQE proposal's P3 (absence is explicit), P4 (delete what nothing uses) and P5 (make 0.12 additive, D1) apply here
unchanged. Two more for the voice messages:

- **P6. The server is the authority for a session's configuration.** A client learns it from discovery
  (`AppServerInfo`) and sends only what it actually wants to override. Fields the server never reads go.
- **P7. State changes say why.** A client (tcnart's avatar, the GUI) must be able to tell "the user interrupted" from
  "noise was ignored" from "nobody addressed the assistant" without reading logs.

## 1. Session control (`control.idl`, `common.idl`)

| id | today | 0.11 | |
|---|---|---|---|
| S1 | `SessionStart` carries `direction`, four `AudioFormat`s, three backend names, `language_hint`, `voice_hint`, `enable_partial_tts`. The server reads none of them (it reads `header`, `identity`, `allow_barge_in`, `enable_partial_stt`, and `enable_partial_llm`, which it then forces to true). tcnart copies the discovery reply's values back into them (`voice_agent.cpp:534–542`). | **`SessionStart { header; identity; boolean allow_barge_in; boolean enable_partial_stt; @optional BargeInMode barge_in_mode; }`** (S6). Formats and backends come from `AppServerInfo` only. `language_hint`/`voice_hint` go until the server can honour a per-session override; then they return as optional fields of S2's replacement. | breaks |
| S2 | `SessionConfigUpdate` (with eight `has_*`/value pairs) and `SttRequest` are never published by any producer; only the observer decodes them. | **Delete both.** A per-session override message, if wanted later, is designed with the server that applies it (optional fields, an acknowledgement). | breaks |
| S3 | `SESSION_STATE_PLAYING` is never entered: the orchestrator goes from `TTS_SYNTHESIZING` to `LISTENING` at `TtsDone`, which arrives when synthesis ends, often seconds before the client has played the reply. tcnart's "speaking" predicate tests for `PLAYING` (`voice_agent.cpp:206`) and never sees it. | `PLAYING` becomes real with S4: `TTS_SYNTHESIZING` → `PLAYING` (synthesis done, audio still playing) → `LISTENING` (the client reports the queue drained). Values unchanged. | semantic |
| S4 | The server cannot know when a reply has been heard. Consequences in the pipeline: a noise during the playback tail starts a turn and the client drops the rest of the reply; the wake word's conversation window counts from the end of synthesis; time-to-first-audio is measured at the server, not at the listener. | **New `PlaybackEvent { MessageHeader header; PlaybackState state; unsigned long long played_samples; unsigned long sample_rate_hz; }`** with `enum PlaybackState { PLAYBACK_STATE_UNKNOWN, PLAYBACK_STATE_STARTED, PLAYBACK_STATE_DRAINED, PLAYBACK_STATE_CLEARED }`, published by the client per turn (`header.turn_id`) on `{session}/control/playback`. `STARTED` at the first audible sample, `DRAINED` when the turn's last chunk has played, `CLEARED` when queued audio was dropped (barge-in, new turn). A client that does not send it keeps today's behaviour (capability, D4). | additive |
| S5 | `SessionStateEvent { header; state; Status status; }`: a return to `LISTENING` looks the same after a completed reply, an ignored noise, an utterance without the wake word, a cancel or a barge-in. | Add **`SessionStateReason reason`**: `enum SessionStateReason { SESSION_STATE_REASON_NONE, _COMPLETED, _BARGE_IN, _NON_SPEECH, _NOT_ADDRESSED, _CANCELLED, _ERROR }`. `status` stays for errors. | breaks (field) |
| S6 | Barge-in is one boolean per session; the server now has modes (`off`, `vad`, `sustained`, `words`; pipeline PR #17) that a client cannot see or choose. | **`enum BargeInMode { BARGE_IN_MODE_OFF, _VAD, _SUSTAINED, _WORDS }`** advertised in `AppServerInfo.barge_in_mode`; a client may lower it with `SessionStart.barge_in_mode` (optional). `allow_barge_in = false` stays as the simple off switch. | breaks |

## 5b. Face animation and the turn timeline (`tts.idl`, `audio.idl`, new `face.idl`)

Goal: blend-shape face animation (e.g. NVIDIA Audio2Face, ARKit-style weights) that a player renders in sync with
the reply's audio. The animation is not produced yet; the structs land now so adding a producer later is additive.

**The turn timeline.** Every position is a sample index on one clock: the turn's synthesized audio, starting at 0
with the first TTS sample of the turn and continuous across the turn's TTS segments (the orchestrator sends one
`TtsRequest` per sentence). A player that knows which sample of the turn it is playing knows which face frame to
show; no wall clock, no clock sync between machines. Today `TtsAudioChunk` has no position, and the downlink
`AudioOpusFrame.first_sample_index` counts per session and resets on a cancel.

| id | today | 0.11 | |
|---|---|---|---|
| F1 | `TtsAudioChunk` has `chunk_index` per request only. | Add **`unsigned long long turn_sample_index`**: its first sample's position on the turn timeline, at `format.sample_rate_hz`. The TTS service keeps it running across the segments of a turn. | breaks (field) |
| F2 | Downlink `AudioOpusFrame.first_sample_index` is session-relative. | Add **`unsigned long long turn_sample_index`** (egress keeps the TTS position, rescaled if it resamples); `first_sample_index` stays the session-continuous counter for loss detection. | breaks (field) |
| F3 | — | **`FaceAnimationLayout { string layout_id; FaceRig rig; sequence<string> channel_names; sequence<string> emotion_names; float frame_rate_hz; }`**, `enum FaceRig { FACE_RIG_UNKNOWN, FACE_RIG_ARKIT_52, FACE_RIG_CUSTOM }`. ARKit's 52 names in their canonical order for `ARKIT_52`; any names for `CUSTOM`. Advertised in `AppServerInfo.face_layouts` (and with capability `face_animation`), so chunks need not repeat the names. | additive (with D1) |
| F4 | — | **`FaceAnimationChunk { MessageHeader header; string layout_id; unsigned long chunk_index; boolean is_final_chunk; unsigned long long turn_sample_index; unsigned long sample_rate_hz; float frame_rate_hz; unsigned long frame_count; sequence<float> weights; @optional sequence<float> emotion_weights; @optional sequence<float> head_rotation; @optional sequence<float> eye_rotation; }`**. `header.turn_id` is the turn; frame *i* is shown at turn sample `turn_sample_index + round(i * sample_rate_hz / frame_rate_hz)`. `weights` is frame-major, `frame_count × channel_count`, 0..1. Rotations are per frame (quaternion x, y, z, w; eyes left then right). Topic `{session}/face/main/animation`. | additive (with D1) |
| F5 | — | Cancellation follows the audio: a player drops face chunks of a turn whose audio it cleared (barge-in, `PlaybackEvent` `CLEARED`, S4); a producer stops on the same `SessionCancel` as TTS. A chunk may arrive before or after the audio it belongs to; the player buffers by position (a few hundred ms is typical for Audio2Face). | semantic |

Notes:
- The producer can be a face service that subscribes to `TtsAudioChunk` (it inherits `turn_sample_index` from the
  audio it animates) or a TTS that emits visemes itself; the player does not care.
- 52 floats at 60 fps is about 12.5 KB/s per session, well below the audio; quantising to 8 or 16 bit can come later
  as an additive field if needed.
- A player that renders on a different machine than the one playing the audio needs only the turn timeline plus its
  own playback position, which `PlaybackEvent` (S4) reports.

## 6. Not in 0.11 (kept out on purpose)

- Per-session voice or language overrides (S1/S2): only once the server applies them, with an acknowledgement.
- Wake-word configuration on the wire: it is a server setting (live parameters through the membership parameter
  service), not a session field.
- Changing the audio sample layout (`samples_f32`, Opus): it works and is performance-tuned. (`ShmRef` is deleted
  instead, A2.)
- A face-animation producer (Audio2Face integration): only its wire types are in 0.11 (§5b).

## 7. Rollout

Joins the SQE 0.11 lockstep (PR #35 §9): tcn_schema 0.11.0 with a `MIGRATION-0.11.0.md` section for
`conversation_msgs`, then the pipeline (app-server, clients, observer; its pinned `idl/` copy is refreshed from the
merged commit) and tcnart (`voice_agent.cpp`, regenerated Unity types). The additive items (S4, T1) could also ship
first in a 0.10.x micro release if tcnart wants playback events earlier.

**Size:** the IDL is a day (two with §5b). The pipeline is a few days (S4/S5 behaviour in the orchestrator and both clients, the
rest is mechanical). tcnart: `voice_agent.cpp` stops echoing discovery values (S1), sends `PlaybackEvent` (S4),
and maps reasons (S5).

## 8. Decisions needed

- **D1** (shared with PR #35): XCDR2 `@appendable` for `conversation_msgs` too. Recommended: S4/T1-style additions
  then stay additive after 0.11, and L2 needs `@optional`. **IVA: yes.**
- **D2** (S1/S2): delete `language_hint`/`voice_hint` now, or keep them as unused optional fields until the override
  exists? **IVA: delete.**
- **D3** (S4): where playback is measured. Client-side (proposed: the client knows what it played) or inferred at
  the server from `TtsDone.total_samples` (T1) and wall time only. **IVA: client-side; tcnart to confirm.**
- **D4** (S4/D1): capability strings, or a version field per feature? **IVA: capability strings.**
- **D5** (F3/F4): the layout once in discovery (proposed), or the channel names in every chunk (self-contained but
  repetitive)? And: is ARKit 52 the right default rig for tcnart's avatars, or does it use Audio2Face's own set?
  **IVA: the layout once in discovery; the rig is tcnart's choice.**
