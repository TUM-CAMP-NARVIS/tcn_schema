# HumanPose for 0.11: joint draft (tcnart and HTA)

2026-11-27. Status: **draft for discussion**. It follows the agreement on #38 (A6) and #39 (XC2), recorded in #40, and
**includes HTA's answers of 2026-11-27 on #38**. Package and type names assume #39's reorganisation (`tcn_types`,
`sqe_msgs`) and XCDR2 `@appendable` (#35 D1). Rename freely to the final layout.

## 1. Roles

| Message | Producer | Consumer | Rate |
|---|---|---|---|
| `PersonTrackingMessage` (same role as today; now uses `JointSet`) | HTA's multi-camera tracker | HTA's stabiliser, tcnart's `human_pose` feature | per capture group |
| `HumanPoseMessage` | HTA's pose tracker after stabilising; tcnart's `human_pose` feature; tcnart apps that self-track their user (`TCN_LITE` from XR poses, `TCN_BODY` from IK or vision) | avatars (Unity, Unreal), agents, web controller | per capture group / per frame |
| `HumanShapeMessage` | the same producer | the same consumers | latched, re-published on change |
| person stream properties (the descriptor's person case, #35 S1 / #38 A2) | the same producer | the same consumers | latched |

**Defaults for now (HTA):**
- HTA publishes `HALPE26` or `COCO17` positions only; its stabiliser has no IK or rotation output yet.
- `TCN_BODY` with rotations follows once HTA's rotation model exists.
- Until then the conversion for avatars lives in tcnart's library.

## 2. IDL draft

```idl
// Referenced, defined elsewhere in 0.11:
//   tcn_types::StreamHeader   (#38 A1: stamp, ClockDomain, frame, group_id — group_id matches a HumanPose message
//                              to the PersonTracking group it came from)
//   tcn_types::ClockDomain    (#38 A1; id per #37 T10)
//   sqe_msgs::SRFrameRef      (#35 N2; the frame, e.g. the domain node @tcn/loc/pcpd::world)
//   tcn_types::Vector3, Quaternion

module tcnart_msgs { module msg {

  // ---- joint sets: one table (§4), used by PersonTracking and HumanPose ----
  @appendable enum JointSet {
    JOINT_SET_UNKNOWN,
    JOINT_SET_COCO17,       // HTA tracker (17)
    JOINT_SET_HALPE26,      // HTA tracker (26)
    JOINT_SET_TCN_LITE,     // headset user from XR poses (7, §4.3)
    JOINT_SET_TCN_BODY,     // full body for IK and avatars (20) = today's tcnart_body_v1 (§4.4)
    JOINT_SET_SMPL_24,      // SMPL body joints: the order of SmplParams.pose only
    JOINT_SET_SMPLX_55      // SMPL-X joints: the order of SmplParams.pose only
  };

  @appendable enum PersonState { PERSON_STATE_UNKNOWN, PERSON_STATE_TRACKED, PERSON_STATE_COASTING, PERSON_STATE_LOST };
  @appendable enum JointSource { JOINT_SOURCE_UNKNOWN, JOINT_SOURCE_OBSERVED, JOINT_SOURCE_DERIVED, JOINT_SOURCE_DEFAULTED };

  @appendable struct HumanJoint {
    tcn_types::Vector3 position;                // m, in the stream's frame
    float confidence;                           // [0,1]
    JointSource source;
    @optional tcn_types::Quaternion rotation;   // stream frame, relative to the joint set's rest pose (§3.1)
  };

  @appendable enum SmplModel  { SMPL_MODEL_UNKNOWN, SMPL_MODEL_SMPL, SMPL_MODEL_SMPLH, SMPL_MODEL_SMPLX };
  @appendable enum SmplGender { SMPL_GENDER_NEUTRAL, SMPL_GENDER_FEMALE, SMPL_GENDER_MALE };

  @appendable struct SmplParams {                 // per frame; the shape (betas) is in HumanShape
    SmplModel model;
    tcn_types::Vector3 global_orient;             // axis-angle, rad
    tcn_types::Vector3 translation;               // m, stream frame
    sequence<tcn_types::Vector3, 54> pose;        // axis-angle per joint, PARENT-relative, SMPL's own order (§3.2)
    sequence<float, 100> expression;              // SMPL-X only
  };

  @appendable struct HumanPose {
    uint32 person;                                // stable per producer; never reused within a session
    @optional string<128> member;                 // the session member's client id when the person is that user
    PersonState state;
    float confidence;                             // [0,1], the person as a whole
    sequence<uint32, 8> source_ids;               // merged source tracks, newest first; may be empty
    sequence<HumanJoint, 64> joints;              // in the stream's joint set's order
    @optional SmplParams smpl;
  };

  @appendable struct HumanPoseMessage {
    tcn_types::StreamHeader header;               // one capture group: stamp, ClockDomain, frame, group_id
    JointSet joint_set;
    uint16 joint_set_version;
    sequence<HumanPose, 32> persons;
  };

  @appendable struct HumanShape {                 // keyed by person
    uint32 person;
    JointSet joint_set;
    uint16 joint_set_version;
    sequence<float, 64> bone_lengths;             // m, the joint set's bone list; NaN while not frozen (§3.4)
    @optional SmplModel smpl_model;
    @optional SmplGender smpl_gender;
    sequence<float, 300> smpl_betas;              // empty without SMPL
  };

  @appendable struct HumanShapeMessage {
    tcn_types::StreamHeader header;
    sequence<HumanShape, 32> persons;
  };

  // Latched stream properties of a person stream (the descriptor's person case, #35 S1 / #38 A2).
  @appendable struct PersonStreamInfo {
    JointSet joint_set;
    uint16 joint_set_version;
    tcn_types::Vector3 up;           // unit, in the stream's frame (HTA: per site, from the rig calibration);
                                     // deprecated once the frame states its real axes (#38 A9)
    float coast_limit_s;             // how long an unmatched person is predicted (HTA: max_gap_s, default 1.0)
    float reid_window_s;             // after this, LOST is final (HTA: 5.0)
    string<32> smoothing;            // e.g. "one_euro", "off"; parameters stay in the stream's properties
  };

}; };
```

`PersonTrackingMessage` changes in step:
- its free `joint_set` string becomes `JointSet` plus `joint_set_version`;
- its `up` and `world_frame` move into `StreamHeader` and `PersonStreamInfo`, per #39's `frame_id` and `world_frame`
  item.

## 3. Conventions

### 3.1 Rotations (agreed)

`HumanJoint.rotation` is the orientation of the joint's frame in the stream's frame, relative to the joint set's rest
pose (`tcnart_body_v1`'s existing definition, generalised): the joint's outgoing bone points along `rotation ·
d_rest`. When every rotation is identity, the T-pose sits with the body frame B's axes on the frame's axes. Rotations
therefore never depend on `up`. "Forward" needs no field, because the rest pose faces the person's own heading.

Rest-pose-relative and parent-relative rotations are never converted on the wire, and neither are joint sets. The
conversions live in the client libraries.

### 3.2 SMPL (agreed)

- **`SmplParams.pose`** is SMPL's parent-relative axis-angle, in `JOINT_SET_SMPL_24` or `_SMPLX_55` order.
- **Rotations alongside.** A producer that fits SMPL also sends `joints[].rotation` in its stream's joint set.
- **Numbers only.** The schema carries no model data. tcnart's SMPL use is a build option, off by default (licence).

### 3.3 Life cycle (HTA)

- **`COASTING`:** an unmatched confirmed person is predicted to the group's time for up to `coast_limit_s`.
- **Re-identification:** it can bring the same `person` back within `reid_window_s`.
- **`LOST`:** sent once, only when the id can no longer come back. A person never returns after `LOST`.

### 3.4 Shapes (HTA)

- `bone_lengths` is NaN while not frozen. HTA's bone references become valid once a track is confirmed.
- The shape is re-published whenever it changes.

### 3.5 One person, two producers (agreed)

- **De-duplication** is by `member`. Consumers prefer the self-tracked head and hands, and the tracked body.
- **HTA's tracker** sets `member` once it links a tracked person to a headset user (head near the headset's SQE pose).
  That is future work; until then it leaves `member` empty.
- **A self-tracking tcnart app** always sets `member`.

### 3.6 Time

- **One stamp per message.** A message is one capture group; coasting persons are predicted to the group's time.
- **`StreamHeader.group_id`** matches a `HumanPoseMessage` to its `PersonTrackingMessage` group.

## 4. The joint-set table

- **Format:** one machine-readable file in tcn_schema (JSON or YAML), versioned per set with `joint_set_version`.
- **Contents per set:** joint names, parents, bones, and the rest pose (body frame B and bone directions).
- **Generated from it:** the IDL enum, C++ and C# arrays, and the docs (replacing `JointSets.md`).
- **Versioning:** a set's order never changes within a version, and consumers refuse an unknown (set, version) pair
  loudly.

### 4.1 COCO17, HALPE26 (HTA)

HTA drafts these rows from today's `JointSets.md`.

### 4.2 SMPL_24, SMPLX_55

Joint names, parents and order only, for `SmplParams.pose`; no model data.

### 4.3 `TCN_LITE` (7): a headset user from XR poses

- **Order:** 0 head, 1 chest, 2 pelvis, 3 left hand, 4 right hand, 5 left controller, 6 right controller.
- **Chest and pelvis** are DERIVED, as tcnart's lightweight avatars derive them today.
- **Controllers** are DEFAULTED with confidence 0 when not held.
- **Hands** are the wrist frames.
- **Rest pose:** that of `TCN_BODY` for the shared joints.

### 4.4 `TCN_BODY` (20) = today's `tcnart_body_v1`

**Answer to HTA's question on #38:**
- `TCN_BODY` **is** `tcnart_body_v1`: the same 20 joints, 19 bones and T-pose rest pose in body frame B, as
  `JointSets.md` defines them today, as version 1.
- The 24-joint SMPL topology in tcnart's earlier draft is withdrawn. `tcnart_body_v1` maps directly from HALPE26,
  which is HTA's default output, and keeps SMPL out of tcnart's own skeleton.
- The table retires the string `tcnart_body_v1` explicitly, in favour of `JOINT_SET_TCN_BODY` version 1.
- Mapping to and from SMPL stays in the client library.

**Joints:**

| index | joint | index | joint |
| --- | --- | --- | --- |
| 0 | pelvis (root) | 10 | left wrist |
| 1 | spine | 11 | right wrist |
| 2 | chest | 12 | left hip |
| 3 | neck | 13 | right hip |
| 4 | head | 14 | left knee |
| 5 | head top | 15 | right knee |
| 6 | left shoulder | 16 | left ankle |
| 7 | right shoulder | 17 | right ankle |

**Bones and rest pose:** as in today's `JointSets.md` §`tcnart_body_v1`.
