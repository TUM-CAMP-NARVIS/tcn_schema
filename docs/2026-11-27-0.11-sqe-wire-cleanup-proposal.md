# Proposal: tcn_schema 0.11 — the SQE wire cleanup

2026-11-27. Status: **proposal, for review.** Scope: every type, key and convention between SQE clients and the
engine (`tcnart_msgs/msg/SpatialRelations.idl`, `StreamDescriptor.idl`, `PoseTracking.idl`, `Types.idl` where the SQE
reads it, `tcnart_msgs/rpc/SIS.idl`, and the contract library under `src/sqe/`).

Sources:
- two audits, of this repository and of the engine (`spatial_query_engine_rs`: `docs/reference/compatibility-breaks.md`
  B1–B97, `protocol.md`, `data-model.md`, `docs/internals/follow-ups.md`);
- `MIGRATION-0.10.7.md` §"Planned: a 0.11 schema refactoring";
- the engine's node-domains spec.

Item ids (`N3`, `R2`, …) are for the review discussion.

## 0. Why one break, and what it buys

0.10.x stayed additive for a reason: B76 compares `major.minor`, so a minor bump forces every SQE peer to rebuild in
lockstep, sensors and trackers included. Since 0.10.0 that discipline has left scars:
- **Structure is encoded in strings:** domain ids, marker domains, marker names, templates, derived-edge names.
- **Fields are kept only for their layout:** misnamed fields, filler booleans, `_COV` union cases.
- **Replies are inconsistent:** five status enums, and engine identity in some replies but not others.
- **Shims for clients that no longer exist** are still in place.

0.11 is the one release where all of it can be fixed at once. It should also make the next additions cheap, which is
principle P5.

### Principles

- **P1. Names are opaque.** Nothing on the wire is parsed out of a name or a key segment. Identity, scope, domain,
  provenance and kind are fields.
- **P2. One reply shape.** Every reply starts with the same header and uses one status vocabulary. The domain outcome
  goes in a second, named field.
- **P3. Absence is explicit.** No sentinel values, no "0 or 1 entries" sequences, no "empty means not asked".
- **P4. Delete what nothing uses.** Every legacy shim and dead field goes. Removing them is the point of a break.
- **P5. Make 0.12 additive by construction.** Adopt appendable types (XCDR2), so that adding a trailing field stops
  being a wire break (see D1).

## 1. Identity and naming (P1)

| id | today | 0.11 |
|---|---|---|
| N1 | A domain node's `SRNode.name` is `@{domain}::{name}` (B94). | Add **`string domain` to `SRNode`**; `name` is bare again. The `@` sigil, `parse_domain_node_id`, `DomainNodeId` and the `@…` edge-name spelling (B95) go. |
| N2 | `SISFrameRef { client, node }`. An empty `client` means "shared" (B94, B96), and the node can be `@…` or `<device>:::*`. | **`SRFrameRef { SRNodeScope scope; string owner; string name; SRFrameSelector selector; }`**. `owner` is the fragment for LOCAL, the domain for DOMAIN, and empty for GLOBAL. `selector` is `FRAME` or `INSTANCES`, which replaces `:::*` (B87). Used everywhere a frame is named. The contract library's `FrameRef` gets `local()`, `global()` and `domain()`. Today a Global ref cannot be built at all: `parse` refuses an empty client. |
| N3 | Edge endpoints `SREdge.source`/`target` are bare names, resolved against the sending fragment first and then globally. | Endpoints are **`SRFrameRef`**, with no resolution guesswork. Inside a join, a LOCAL ref with an empty owner means "this fragment". |
| N4 | Relations are named by a bare string in `derived_from`, `SISPlanHop.derived_from`, `correlated_via`, `SISGraphQueryReply.path`, `SISBlockingRelation` and remove requests. | Add **`SRRelationRef { SRFrameRef source; SRFrameRef target; string name; }`** and use it in all of those places. `SISEdgeRemoveRequest` carries the full ref, which fixes the ambiguous removal (ruling R31). |
| N5 | Marker nodes `{prefix}{system}___sis_marker__{id}` and marker edges `{camera}:::{marker}` are composed and parsed by convention (B30, B72, B94, B95). | **Structured materialization.** A materialized node carries `SRMaterialization { SRNodeRef template_device; MarkerType marker_type; string marker_system; uint32 marker_id; string domain; }`, which replaces `materialized_from`/`materialized_id`. Names are engine-chosen and opaque. Clients find markers by these fields (a graph query filter, G3), not by composing names. The `_mt*_` prefix table and `marker_node_name` go. Marker edges carry `SREdge.materialized = true`. |
| N6 | The marker domain is appended to `marker_system` as `{system}@{domain}` (B97). | A **`string marker_domain`** next to `marker_system` on the descriptor's tracker part (see S1). |
| N7 | `SRNodeTemplate` (`node_template`, "0 or 1 entries") is never read; templating is driven by the descriptor. | **Delete `SRNodeTemplate`**. A template claim is the descriptor plus `marker_system` and `marker_domain`. If declared templates are wanted later, they come as a real feature. |
| N8 | Derived edges are recognised by the `sqe.derived:` name prefix (B31, B47). | Add **`SREdge.derived`** (a boolean, or part of `SREdgeKind`, E3). `derived_from` holds `SRRelationRef`s. The name is opaque. |
| N9 | Fragment identity is stated twice: in the key prefix and in `SRGraph.name` / `SISLeaveRequest.client`. The latter is decoded and then ignored. | Drop `SISLeaveRequest.client`. `SRGraph.name` becomes optional display text. The key is the identity. |
| N10 | `SISTargetAlias.system` packs family and variant (`aruco:DICT_4X4_50`). `SISGraphChangeNotification.origin` is a client id, a requester, or the literal "engine". | The alias becomes `family` + `variant` + `key`. The origin becomes `SISChangeOrigin { kind (CLIENT, OPERATOR, ENGINE); string id; }`. |

## 2. Replies and status (P2)

| id | today | 0.11 |
|---|---|---|
| R1 | Five status enums (mutation, relation stream, graph query, target query, sample), each re-declaring REJECTED/UNAVAILABLE/UNKNOWN_*. `SISGraphQueryStatus` is reused by pattern, info, fragments, explain and txlog replies; explain uses `UNKNOWN_FRAME` to mean "no such handle". | **`enum SISStatus { OK, REJECTED, UNAVAILABLE, UNKNOWN_CLIENT, UNKNOWN_FRAME, NOT_FOUND, TRUNCATED, CONFLICT, NOT_IN_SCOPE }`**, one vocabulary. |
| R2 | `detail` sits at positions 2–5. Engine identity appears in some replies (mutation, sample, info), only the epoch in others (status, plan, change notifications), and nowhere in the rest (stream reply, graph, pattern, target, explain). Ingest-level refusals carry an empty id and epoch 0 (B74). | **`SISReplyHeader { SISStatus status; SISReason reason; string detail; string engine_id; uint64 engine_epoch; }`**, first in every reply and notification, filled at every refusal site including ingest. |
| R3 | `SIS_RS_REJECTED` covers both malformed requests and conflicts (B28). `CLOCK_DOMAIN_MISMATCH` means "refused" in a reply and "parked" in a status (B79). `PENDING` lumps uncalibrated, awaiting descriptor, starved, resolving and withdrawn together, and clients parse `detail`. | Separate the **request outcome** (header `status` + **`SISReason`**: MALFORMED, TERMS_CONFLICT, NOT_PERMITTED, …) from the **relation state**: `SISRelationState { ACTIVE, PENDING, INACTIVE }` plus **`SISParkReason { UNCALIBRATED, AWAITING_DESCRIPTOR, INPUT_STARVED, RESOLVING, WITHDRAWN, CLOCK_DOMAIN_MISMATCH }`**, ordered logically. |
| R4 | `stop` always answers INACTIVE, even for a stream that never existed (B28, B36). | `NOT_FOUND` for an unknown handle. |
| R5 | Clients cannot tell an engine without a feature, or a client outside every scope, from an absent engine: they time out (B81, B93) or read `op/info` (`protocol_break`). | **Capabilities.** The join reply (and an unscoped `sqe/{engine}/info` key) carries `uint32 protocol_break` and `sequence<string> capabilities` (`sample`, `domain`, `rational_lens`, `marker_domain`, …). An engine answers `NOT_IN_SCOPE` on a small, explicitly scoped catch-all key instead of silence. That can be its own decision (D4). |
| R6 | Status puts have no sequence number, so ordering relies on the engine awaiting each put (B14). | `uint64 sequence` on status and plan notifications, gapless per handle (as `op/changes` already does). |

## 3. Handles, keys and topics

| id | today | 0.11 |
|---|---|---|
| H1 | The same value is called `handle`, `topic` and `output_topic` (`SISRelationStreamStatusNotification.output_topic` was kept for its position). | One name, **`handle`**, everywhere. |
| H2 | `{handle}/status` and `{handle}/plan` are derived by suffix, and the topic shapes are "provisional" (B14). | The start reply carries **`data_topic`, `status_topic`, `plan_topic`** explicitly. Clients stop composing them; the contract library keeps the builders only for the engine. |
| H3 | The route epoch travels in a 13-byte Zenoh attachment ("SQE pose attachment v1", B80). | Relation-stream output gets its own type, **`SISRelationOutput { uint64 engine_epoch; uint64 route_epoch; uint64 sequence; TargetTrackingMessage targets; }`**, or the epoch moves into the payload header. The attachment goes. |
| H4 | Key families mix vocabulary: `/sis/component/*` holds node types and `/sis/relation/*` holds edge types. The registry is per engine but reached through a client key. | Rename to **`/sis/node/*`** and **`/sis/edge/*`**, or rename the types to relation; pick one (G1). Consider moving `target/*` to `sqe/{engine}/targets/*`. |
| H5 | Marker announcements encode the marker name in a liveliness key segment, `{client}/cfg/marker/{device}/{marker}`. | `{client}/cfg/marker/{device}/{marker_id}`, the **id** and not a name (N5). |

## 4. Edges, transforms, intrinsics

| id | today | 0.11 |
|---|---|---|
| E1 | `SRTransformType` has separate `_COV` cases because a field could not be appended to a union case (B60). | **POSE6D and TRANSLATION3D carry the covariance** (an `SRCovariance6` / `SRCovariance3`: packed upper triangle, explicitly optional). The `_COV` cases go. |
| E2 | `SRIntrinsics.distortion_model` is a free string; the IDL comment names `opencv_fisheye`, which is unimplemented, and omits `opencv_rational` (B96). `sequence<double, 8>` caps the coefficients. There is no validity radius. | **`enum SRDistortionModel { NONE, OPENCV_RADTAN, OPENCV_RATIONAL }`** (fisheye appended when implemented). Coefficients become `sequence<double, 16>`. Add an optional **`metric_radius`**. |
| E3 | `SREdgeTemporalType` mixes timing (static, uncalibrated, calibrated, dynamic) with kind (`PROJECTION`) and provenance (`DYNAMIC_INFERRED`, which overlaps `derived_from`). | Split into **`SREdgeTiming`** (STATIC, STATIC_UNCALIBRATED, STATIC_CALIBRATED, DYNAMIC), **`SREdgeKind`** (POSE, PROJECTION) and **`derived`** (N8). |
| E4 | `stream_item_id` + `stream_item_bound` (B72) appear in three spellings (`SREdge`, `SISPatternSegment`, `SISPlanInput.entry_*`). | One optional **`uint32 entry_id`** (or a union `SREntryBinding`), used in all three. |
| E5 | SREdge's trailing fields (B65, B66, B72) sit where they were appended, and B66 warns that one-byte appends hide in CDR padding. | **Reorder** fields by meaning; with P5 the padding hazard stops mattering. |
| E6 | Derived edges are written without covariance. A path mixing stated and unstated covariances under-reports its uncertainty (follow-ups). | Output targets carry **`covariance_hops` / `total_hops`** (completeness), and a derived edge states its composed covariance or says it has none. |

## 5. Streams and requests

| id | today | 0.11 |
|---|---|---|
| S1 | `StreamDescriptorMessage` is one flat struct of video, H26x, audio and tracker fields. `frame_rate` is `uint32` here and `double` elsewhere; `marker_type` also drives naming. | **A common header plus a union per sensor kind**: `SISTrackerDescriptor` holds `marker_type`, `marker_system`, `marker_domain`, latency, clock domain and nominal accuracy (`SRCovariance6`, the default weight for fusion). `double frame_rate` everywhere. Media fields stay in their own case. |
| S2 | `TargetTrackingMessage.target_origin` is ignored, with a warning only. `is_tracked`/`quality` are not read. | **Remove `target_origin`**; offsets belong in the graph. Keep `is_tracked`. Decide on `quality` (G2). |
| S3 | Start, explain and sample repeat the request terms, and explain lacks `evaluation`/`reoptimise`. | **`SISRelationTerms { SRFrameRef observer; SRFrameRef target; SRStreamTrigger trigger; double freshness_bias; SISReoptimisePolicy reoptimise; SISEvaluationMode evaluation; SISFusionPolicy fusion; }`**, embedded in all three. `SISFusionPolicy` (BEST_PATH by default, plus FUSED and FILTERED) is the term the fusion design needs. Only BEST_PATH is implemented at 0.11; the field is in place. |
| S4 | Kind-dependent request fields are "ignored, not refused" (graph query, target query, explain). | **Unions switched on kind.** |
| S5 | "Empty means absent" for whole structs (`plan` in stream, sample and explain replies; `live`). Filler `boolean unused` members in union cases. | Explicit optionals (P3). |
| S6 | `SISTranslationPlan.plan_version` duplicates the schema version, and `engine_epoch` was inserted mid-struct (0.10.0). | Drop `plan_version`; the schema version is the version. |

## 6. Delete (P4)

- **Legacy and dead types:**
  - `rpc/SpatialRelations.idl`: `SRNodeRef`, `SRGraphPublish*`, `SRGraphQuery*` (legacy `RPCResponseStatus`). Neither the engine nor sqe_client_cpp uses them. *Check tcnart and HTA before deleting.*
  - `SRNodeTemplate` (N7).
  - `target_origin` (S2).
- **Engine shims that go with 0.11:**
  - the warning subscribers for a `put` on mutation keys (B73);
  - marker discovery from poses (B90). This is blocked until every publisher announces markers. **artekmed is the known holdout.**
  - the inactivity sweep and heartbeat fallback for clients without a liveliness token (B41);
  - re-deriving unqualified marker announcements (B94; moot after H5);
  - padding a short pre-0.9 descriptor;
  - accepting unversioned payloads (B76): the `tcn_schema=` parameter becomes **mandatory**.
- **Contract library:**
  - `kProtocolBLevel = 78` and the separate session and contract floors become one value, generated with the release;
  - the hand-mirrored enums (`Status`, `TriggerKind`, …) with mixed `int32`/`uint32` bases are generated from the IDL, or at least use one base;
  - `Error::IllegalCharacter` reused for an unknown ordinal or a malformed id gets proper codes.

## 7. Encoding and versioning

- **V1:** the annotation becomes `application/cdr;{TYPE};tcn_schema=0.11`, mandatory. The media type is matched exactly,
  not by substring.
- **V2 (P5, decision D1):** CDR v2 / XCDR2 with `@appendable` on every SQE type. A peer can then decode a payload with
  more trailing fields than it knows, and 0.12 can add fields without a lockstep rebuild; only reordering or removal
  would still break. It costs a DHEADER per appendable struct, plus support in the engine's Rust CDR codec, fastcdr (it
  has it), the Unity C# generator, and the web controller's decoder.
- **V3:** one request-to-key-to-reply table, generated from IDL annotations, shared by the contract library and the
  engine. This replaces the hand-kept `session.h` table and the engine's `messages.rs` wire-name list.

## 8. Not in 0.11 (kept out on purpose)

- Fusion behaviour itself, beyond the `SISFusionPolicy` term (S3). That is the fusion design.
- A shared registry across daemons (waits for the persistence move, TCN-202).
- New sensor kinds.

Each can land additively after 0.11, if V2 is adopted.

## 9. Rollout

The 0.10.0 lockstep again:
1. tcn_schema **0.11.0** (IDL, contract library, `MIGRATION-0.11.0.md` with a per-consumer checklist).
2. Engine (one B-number for the whole break), with the shims removed.
3. sqe_client_cpp **0.7.0**, then sqe_local.
4. Consumers: tcnart (Unity C# regenerated), HTA services, trackers (every pose publisher, because of S2), the web
   controller, sqe-calibrate (in the engine repository).

A cut-over day per site (camp, narvis), with the 0.10 build kept installable for rollback. The IVA change joins this
release.

**Estimated size:** the IDL and contract library are about a week. The engine is about two weeks; N2/N3/N5 touch
resolution, persistence and templating. sqe_client_cpp is days. Consumers vary, the largest being tcnart's
regeneration and HTA's naming code.

## 10. Decisions needed

- **D1** (V2): adopt XCDR2 `@appendable`? Recommended. It is what stops this from recurring.
- **D2** (N2): `SRFrameRef` as a struct with a `scope` discriminator (recommended), or an IDL union per scope?
- **D3** (H4 / G1): vocabulary. Node/edge (matches the types) or frame/relation (matches the protocol prose)? The
  keys and types follow.
- **D4** (R5): an explicit `NOT_IN_SCOPE` answer needs an engine to subscribe beyond its scope, which is a deliberate
  choice on a network shared by several engines. Alternatively, capabilities only.
- **D5** (§6): delete marker discovery from poses now (artekmed must announce markers first), or keep it one more
  release.
- **G1**: one term each for node/component/frame, edge/relation, and graph/fragment.
- **G2**: keep or drop `Target.quality`.
- **G3**: graph query filters by `materialized`/`derived`/`marker_*` fields replace name-prefix filtering (N5, N8).
