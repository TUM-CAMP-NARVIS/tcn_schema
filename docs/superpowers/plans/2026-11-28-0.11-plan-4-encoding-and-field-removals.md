# tcn_schema 0.11, Plan 4: Encoding Rules and Field Removals — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put every tcn type under the 0.11 encoding rules, and remove the fields nobody writes, outside the SQE.
- **Encoding:**
  - explicit `@appendable` / `@final` (E1, E7);
  - XCDR2 with encapsulation `00 09` (E1, E9);
  - the annotation `tcn_schema=0.11` (V1);
  - golden files that prove XCDR2 and type evolution (E8, O8).
- **Enums outside `sqe_msgs`:** every enum starts with `…_UNKNOWN`/`…_NONE` (E6), and every enumerator carries the
  enum-name prefix (O5).
- **Field removals:** F1, F2 and F5 of #39 §4.5, with the decided exceptions.

**Roadmap change:** the decided Plan 4 is split in two, so the teams adapt the SQE types once, not twice:
- **this plan:** encoding and hygiene for every package, plus the field removals outside the SQE;
- **Plan 5:** the #35 SQE redesign, including its field removals (F3, F4) and its enums (`SISStatus` replaces five
  status enums);
- **Plan 6:** the #36, #37 and #38 changes, HumanPose, and `0.11.0-rc1`.

**Architecture:** IDL edits by small, reviewable scripts that record what they change:
- `tools/idl/enum_renames_0_11.json` holds the per-enum rename table and is the source of the migration table;
- the field removals are text edits of single members, checked by `tools/idl_cli.py moves` with an "expected
  differences" list.

**Test runtime:** the round-trip and golden tests encode tcn types as XCDR2 and ROS types as XCDR1. A test-only
evolution IDL proves that a shorter (older) and a longer (newer) appendable type decode each other.

**Spec:**
- `docs/proposals/0.11-decisions.md` §2 (E1–E9, V1), §4 (F-rule and exceptions), §3 (O5–O8);
- `docs/proposals/2026-11-27-0.11-schema-housekeeping-proposal.md` §2 and §4.5 (F1, F2, F5 tables).

## Global Constraints

- **Extensibility (E1, E7):** every tcn struct, union and enum is annotated explicitly (E1 names structs and
  unions; the lint rule also requires enums, where it has no wire effect, since an enum is always an int32).
  - `@final` on `tcn_types::msg::{Vector2, Vector3, Quaternion, RigidTransform}` and `sqe_msgs::msg::SRPoint2D`;
  - `@appendable` everywhere else (sqe_msgs included);
  - the generator flag `-de appendable` is passed explicitly (O6);
  - ROS types stay `@final` (Plan 2); this includes `builtin_interfaces/Time`, the sixth E7 leaf.
- **E4:** `conversation_msgs` payloads carry the encapsulation header like every other tcn type. In this repo that
  only needs the test runtime; the migration log tells IVA that `tcn-wire` must write and check it.
- **Encoding in tests and goldens:**
  - tcn types: `Cdr(…, CdrVersion::XCDRv2)`, `set_encoding_flag(EncodingAlgorithmFlag::DELIMIT_CDR2)`, then
    `serialize_encapsulation()`; encapsulation `00 09`;
  - ROS top-level types: `DDS_CDR`, `00 01` (E2, E3).
- **Annotation (V1):** `tcn::sqe::kWireSchemaVersion` = `"0.11"`, so the encoding is
  `application/cdr;<type>;tcn_schema=0.11`.
- **Enums (E6, O5):** apply `enum_renames_0_11.json` exactly. Packages outside `sqe_msgs` only; Plan 5 does the
  SQE enums.

## Review Focus

1. **A golden file or round trip that still encodes a tcn type as XCDR1,** and so would pass without proving XCDR2.
   The goldens must start with `00 09`, except `std_msgs_Header`, which stays `00 01`.
2. **Evolution in the wrong direction:**
   - V2 bytes decoded as V1 must skip the extra member, using the DHEADER;
   - V1 bytes decoded as V2 must give the default and an absent `@optional`.

   Both directions need a test, with the bytes reviewed.
3. **An enum rename that changes a value nobody expects:** the inserted `…_UNKNOWN` shifts ordinals. The migration
   table must list old name, old value, new name and new value for every enumerator.
4. **A field removed that the decisions keep** (`is_tracked`, `scene_point`, `gaze_space`, `SRNode.active`,
   `calib_topic`), or kept that they remove. The `moves` check with an "expected differences" list is the gate.
5. **`@final` on a type that must evolve,** or `@appendable` on one that must not: only the five E7 leaves are
   `@final`.
