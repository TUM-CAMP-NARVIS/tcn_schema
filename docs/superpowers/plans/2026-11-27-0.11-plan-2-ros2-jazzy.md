# tcn_schema 0.11, Plan 2: ROS 2 interfaces from Jazzy — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Do the whole schema side of ROS 2 robot integration now, so that integrating robots later needs no further
break. Concretely:
- replace the hand-copied 2022 ROS IDL with a tree generated by a script from **ROS 2 Jazzy**;
- mark every ROS type `@final` (byte-compatible XCDR1);
- emit the complete service and action types;
- publish the ROS type names and RIHS01 type hashes that rmw_zenoh needs;
- organise the packages in tiers.

**Architecture:**
- `tools/ros2/` is a standard-library Python package (no empy, no lark, no ROS install).
- **Inputs:** it reads upstream `.msg`/`.srv`/`.action` files from git checkouts at commits pinned in
  `src/dds/ros2/UPSTREAM.lock`.
- **Outputs:**
  - fastddsgen-ready IDL under `src/dds/ros2/<pkg>/{msg,srv,action}/`;
  - the RIHS01 hashes, computed with a port of `rosidl_generator_type_description`;
  - `share/tcn_schema/ros2_types.json`.
- **Committed and checked:** the generated tree is committed. `refresh.py --check` regenerates it and fails on any
  difference.
- **Build:** the package table gains a `tier` field, and CMake/conan build the selected tiers.

**Tech Stack:** Python 3 (stdlib), git, CMake 3.19, fast-dds-gen 3.0.0 / fast-cdr 2.0.0, conan 2.

**Spec:** `docs/proposals/0.11-decisions.md` §5 (R-D1 Jazzy, R2–R6, R3, R-D2 tiers, R-D3 policy) and §2 (E2: ROS
types `@final`, XCDR1); `docs/proposals/2026-11-27-0.11-schema-housekeeping-proposal.md` §3 (R1–R7, the tier table
and rmw_zenoh facts).

## Global Constraints

- **Distro:** ROS 2 **Jazzy Jalisco**. The upstream commit of every package is pinned in `src/dds/ros2/UPSTREAM.lock`
  and resolved from the Jazzy `distribution.yaml` of `ros/rosdistro` (its commit is pinned too).
- **Tiers** (R-D2):
  - `base` and `core` are built by default;
  - `manipulation`, `navigation` and `perception` are optional, but pinned and generated from the start.
- **Tier contents**, exactly as in decisions §5 / housekeeping §3.4 R4:

  | Tier | Packages |
  |---|---|
  | `base` | builtin_interfaces, std_msgs, geometry_msgs, sensor_msgs |
  | `core` | nav_msgs, trajectory_msgs, diagnostic_msgs, visualization_msgs, shape_msgs, std_srvs, stereo_msgs, unique_identifier_msgs, action_msgs, service_msgs, rcl_interfaces, lifecycle_msgs, rosgraph_msgs, statistics_msgs, tf2_msgs, type_description_interfaces |
  | `manipulation` | control_msgs, controller_manager_msgs, moveit_msgs, object_recognition_msgs, octomap_msgs |
  | `navigation` | nav2_msgs, geographic_msgs |
  | `perception` | vision_msgs, pcl_msgs |
- **Every ROS struct is `@final`** (E2), written into the IDL file itself.
- **ROS types keep XCDR1:** `DDS_CDR`, encapsulation `00 01`. The golden file `test/golden/std_msgs_Header.hex` must
  stay byte-identical.
- **Upstream file names (R5):** `Time.idl`, `Duration.idl`, `String.idl`. Every generated file gets the include guard
  `<PKG>_<KIND>_<FILE>_IDL` that docs/idl-style.md requires.
- **No local changes to ROS types (R6):** generated files are never edited by hand.
- **Wire changes allowed against today's copy:** `sensor_msgs/Range.variance` (appended), the `NavSatStatus`
  constants and default, and new types only. Anything else that changes an existing type's layout is a bug.
- **Network:** only `refresh.py` uses it, and only when a developer runs it. Build and tests stay offline. Unit tests
  use committed fixtures.
- **Tests:**
  - `python3 -m unittest discover -s tools -p 'test_*.py' -t .`
  - `ctest --test-dir build/Release` (with `TCN_SCHEMA_BUILD_MSG_TESTS=ON`)
- **Commits:** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `0.11-plan2-ros2`.
- **The migration log** `docs/migration/MIGRATION-0.11.0.md` gets each consumer-visible change, in the task that
  makes it.

## Review Focus

1. **RIHS01 hashes that look right but are wrong.** A single wrong rule makes every hash useless to rmw_zenoh, and no
   local test would notice. The suspects are field order, the type-id table, string capacity versus array capacity,
   nested-type sorting, removing `default_value`, and the JSON separators. Task 3 pins hashes against official Jazzy
   values for msg, srv and action types, including types with nested, bounded and array fields.
2. **IDL that fastddsgen 3.0.0 cannot compile, or compiles to different bytes.** Cases: constants modules, `@default`
   on strings and arrays, bounded strings in sequences, `char` and `byte`, `wstring`. Task 5 builds every tier,
   round-trips every type, and checks the Header golden bytes.
3. **Same-package references written without a package.** `.msg` refers to a type in its own package by bare name
   (`Point`), and `Header` means `std_msgs/Header`. Resolution must follow rosidl. Task 1 tests both.
4. **Services and actions:** `_Event` types must reference `service_msgs/ServiceEventInfo`, and the action types must
   reference `unique_identifier_msgs/UUID` and `builtin_interfaces/Time` exactly as rosidl defines them. The hashes
   of `_SendGoal`, `_GetResult` and the actions themselves depend on it. Task 3 tests a service and an action
   against official hashes.
5. **The tcn packages that include ROS IDL:** `tcnart_msgs/msg/SpatialRelations.idl` includes
   `builtin_interfaces/msg/Time_.idl` today. After the rename every include must resolve, and tcn types that embed
   `std_msgs/Header` must stay byte-identical. Task 5 fixes the includes; the goldens and round trips prove the
   bytes.

### Task 1: `.msg`/`.srv`/`.action` parser

**Files:**
- Create: `tools/ros2/__init__.py`, `tools/ros2/rosmsg.py`, `tools/ros2/tests/__init__.py`,
  `tools/ros2/tests/test_rosmsg.py`, `tools/ros2/tests/fixtures/<pkg>/{msg,srv,action}/*` (small hand-written
  examples).

**Interfaces:**
- Produces (`tools/ros2/rosmsg.py`):
  - `Field(name: str, type: RosType, default: str | None)`.
  - `RosType(pkg: str | None, name: str, array: None | ("fixed", N) | ("bounded", N) | ("unbounded",), string_bound: int | None)`.
    - `pkg is None` means a primitive: `bool, byte, char, float32, float64, int8..uint64, string, wstring`.
  - `Constant(name: str, type: str, value: str)`.
  - `MessageSpec(pkg: str, name: str, fields: list[Field], constants: list[Constant])`.
  - `ServiceSpec(pkg, name, request: MessageSpec, response: MessageSpec)`.
  - `ActionSpec(pkg, name, goal, result, feedback)`.
  - `parse_message(pkg: str, name: str, text: str) -> MessageSpec`; `parse_service(...)`; `parse_action(...)`. The
    separator `---` splits services and actions.
- **Grammar, following rosidl_adapter/parser.py (jazzy):**
  - `#` comments, and comments after a value;
  - a field is `type name [default]`;
  - a constant is `TYPE NAME=value`;
  - `string<=N`, `T[]`, `T[N]`, `T[<=N]`;
  - a bare `Name` resolves to the own package, `Header` to `std_msgs/Header`, `pkg/Name` stays as written;
  - the order of fields is preserved.

### Task 2: IDL emitter, including the derived service and action types

**Files:**
- Create: `tools/ros2/emit.py`, `tools/ros2/tests/test_emit.py`.

**Interfaces:**
- Consumes: Task 1 specs.
- Produces:
  - `expand_service(spec) -> list[MessageSpec]` gives `Foo_Request`, `Foo_Response` and
    `Foo_Event { service_msgs/ServiceEventInfo info; Foo_Request[<=1] request; Foo_Response[<=1] response; }`.
  - `expand_action(spec) -> list[MessageSpec]` gives `A_Goal`, `A_Result`, `A_Feedback`, and:
    - `A_SendGoal_Request { unique_identifier_msgs/UUID goal_id; A_Goal goal; }`
    - `A_SendGoal_Response { bool accepted; builtin_interfaces/Time stamp; }`
    - `A_SendGoal_Event`
    - `A_GetResult_Request { UUID goal_id; }`
    - `A_GetResult_Response { int8 status; A_Result result; }`
    - `A_GetResult_Event`
    - `A_FeedbackMessage { UUID goal_id; A_Feedback feedback; }`

    These names and field orders are those of rosidl_parser/definition.py (jazzy). The action-derived types live in
    module `pkg::action`, the service ones in `pkg::srv`.
  - `emit_idl(pkg: str, kind: "msg"|"srv"|"action", file_stem: str, specs: list[MessageSpec]) -> str`. The output:
    - an include guard `<PKG>_<KIND>_<STEM>_IDL`;
    - `#include "<dep pkg>/<kind>/<Name>.idl"` for each referenced type outside this file (sorted, unique);
    - `module <pkg> { module <kind> { … } }`;
    - per spec, a `module <Name>_Constants { const <idl type> <NAME> = <value>; }` when it has constants (as
      rosidl does), then `@final struct <Name> { … };`;
    - the type mapping: `bool→boolean`, `byte→octet`, `char→uint8`, `float32→float`, `float64→double`, `intN→intN`,
      `uintN→uintN`, `string→string`, `string<=N→string<N>`, `T[]→sequence<T>`, `T[<=N]→sequence<T, N>`, and
      `T[N]` as the member declarator `name[N]`;
    - a default becomes `@default (value=…)` on the member;
    - an empty message gets the member `uint8 structure_needs_at_least_one_member;`, as rosidl does.
- **Note:** IDL file stems equal the upstream file stems (`Time`, `String`). A srv or action file holds all its
  derived types.

### Task 3: Type descriptions and RIHS01 hashes

**Files:**
- Create: `tools/ros2/hashing.py`, `tools/ros2/tests/test_hashing.py`, `tools/ros2/tests/fixtures/official_hashes.json`.

**Interfaces:**
- Consumes: Task 1 specs (including expanded service and action specs from Task 2).
- Produces:
  - `type_description(spec, resolve) -> dict`: the TypeDescription. `resolve(pkg, name, kind)` returns any referenced
    spec.
  - `rihs01(spec, resolve) -> str`, which returns `"RIHS01_" + 64 hex`.
  - The algorithm is a port of `rosidl_generator_type_description/__init__.py` at the rosidl `jazzy` commit
    (`git ls-remote` gives `9bcfabf3`):
    - the field type-id table;
    - capacity and string capacity;
    - the referenced types, collected recursively and sorted by `type_name`;
    - `default_value` removed before hashing;
    - `json.dumps(…, separators=(', ', ': '))` (keep upstream's exact arguments);
    - SHA-256.

    Copy upstream's licence header note (Apache-2.0) into the file.
  - Services hash `{request_message, response_message, event_message}`; actions hash goal, result, feedback,
    send_goal_service, get_result_service and feedback_message, as upstream does.
- **Official values:**
  - Source: the `share/<pkg>/<kind>/<Name>.json` type descriptions in the Jazzy binary packages
    (`ros-jazzy-<pkg>` .deb from packages.ros.org).
  - Fetch them once, extract them into a scratch directory (each .deb in its own new empty directory; parse with
    `python3 -I`), and copy only `{type_name: hash}` pairs into `official_hashes.json`, recording the .deb file names
    and versions in that file.
  - Cases:
    - std_msgs/msg/String: must equal `RIHS01_df668c740482bbd48fb39d76a70dfd4bd59db1288021743503259e948f6b1a18` from
      rmw_zenoh's design doc;
    - std_msgs/msg/Header;
    - geometry_msgs/msg/PoseWithCovarianceStamped (fixed array, nested);
    - sensor_msgs/msg/Range;
    - sensor_msgs/msg/CameraInfo (fixed arrays, strings);
    - visualization_msgs/msg/Marker (unbounded sequences of nested types);
    - std_srvs/srv/SetBool;
    - nav_msgs/srv/GetMap;
    - action_msgs/srv/CancelGoal;
    - tf2_msgs/action/LookupTransform;
    - a type with a bounded string, if Jazzy has one (search with `grep -r '<=' share/*/msg/*.msg`).

### Task 4: `refresh.py`: fetch, lock, generate, and `ros2_types.json`

**Files:**
- Create: `tools/ros2/refresh.py` (CLI `python3 -I tools/ros2_cli.py refresh|check`), `tools/ros2_cli.py`
  (launcher, like `tools/idl_cli.py`), `tools/ros2/tiers.py`, `tools/ros2/tests/test_refresh.py`.
- Create (generated): `src/dds/ros2/UPSTREAM.lock`, `src/dds/ros2/ros2_types.json`.

**Interfaces:**
- `tools/ros2/tiers.py`:
  - `TIERS: dict[str, list[str]]` holds exactly the Global Constraints table;
  - `DEFAULT_TIERS = ["base", "core"]`.
- `UPSTREAM.lock` (JSON):
  - `{"distro": "jazzy", "rosdistro_commit": sha, "repos": {repo_url: {"version": branch_or_tag, "commit": sha}}, "packages": {pkg: {"repo": url, "path": subdir, "tier": tier}}}`.
  - `refresh --update-lock` resolves the lock from rosdistro `jazzy/distribution.yaml`. Parse it with a minimal
    reader for the `repositories: <name>: source: {url, version}` and `release: packages` keys only; no PyYAML.
    Each package's source repository and path are found by scanning the checkout for `<pkg>/package.xml`.
  - Plain `refresh` uses the lock as it is.
- `refresh(dds_ros2: Path, lock: Path, cache: Path) -> None`:
  - shallow-fetches each repo at its commit into `cache`;
  - for every package in every tier: parses, expands, emits IDL into `src/dds/ros2/<pkg>/<kind>/<Stem>.idl`;
  - deletes files of these packages that upstream no longer has;
  - writes `src/dds/ros2/<pkg>/CMakeLists.txt` as one `tcn_add_idl_package()` call;
  - writes `ros2_types.json`.
- `check(...) -> int`: regenerates into a temp directory and diffs against the committed tree; exit 1 on any
  difference.
- `ros2_types.json`:
  - `{"distro": "jazzy", "types": [{"ros_name": "std_msgs/msg/String", "dds_name": "std_msgs::msg::dds_::String_", "cpp_name": "std_msgs::msg::String", "kind": "msg"|"srv"|"action"|"srv_part"|"action_part", "package", "tier", "hashes": {"jazzy": "RIHS01_…"}}]}`.
  - `srv`/`action` entries are the service and action types themselves; their parts are listed with `kind` `*_part`.
  - Other distros' hashes (R7) come in through `--hash-distros kilted,lyrical`: for each listed distro, its sources
    are fetched at the distro's rosdistro commit (recorded in the lock under `"hash_distros"`), and a hash is added
    for every type whose own definition there yields a hash computed the same way. Run it with `kilted,lyrical` for
    this plan.
