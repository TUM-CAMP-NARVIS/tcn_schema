# tcn_schema 0.11, Plan 3: Moves and Deletions — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the tcn packages their 0.11 layout, without changing any field:
- **new packages:** `tcn_types` (shared types) and `sqe_msgs` (the SQE protocol, with `SIS.idl` split by topic);
- **moves:** the parameter RPC into `pcpd_msgs`; `src/dds/custom/` becomes `src/dds/tcn/`; PascalCase file names
  with include guards;
- **deletions:** every type and file that decisions §4 deletes (groups A and B, XA7);
- **for the teams:** a generated old → new type map.

**Architecture:**
- A declarative move list, `tools/idl/moves_0_11.json`, says for each new file which declarations it takes, from
  which old file, into which module, and which declarations are deleted.
- `tools/idl/restructure.py` applies it to the old tree. It cuts each declaration's **original text** (with its
  leading comments and annotations) via parser spans, then:
  - writes the new files with guards and computed `#include`s;
  - rewrites references to moved types to their new fully qualified names.
- `tools/idl/moves.py` compares the old and new schemas:
  - it produces the type map (JSON plus a Markdown table);
  - it proves that every surviving type keeps its layout (members, enumerators and union cases, with type names
    mapped through the moves).

**Tech Stack:** Python 3 (stdlib), CMake, fast-dds-gen 3.0.0 / fast-cdr 2.0.0.

**Spec:**

## Review Focus

1. **Comments that end up next to the wrong declaration.** The text cut must take a declaration's leading comment
   block and nothing of the previous declaration's trailing comment. Task 2 tests it on a fixture with comments
   between declarations; the reviewer reads `Graph.idl` and `Streams.idl`.
2. **A reference left unqualified after a move** that now resolves to nothing (or, worse, to a same-named type in
   another module: `Quaternion` exists in `geometry_msgs` and `tcn_types`). Task 2's layout-equality check maps every
   member type, and fails on any member whose type does not resolve.
3. **An enum or union that changed** while moving: ordinals, discriminator, labels. Covered by the layout check.
4. **The contract library's forward declarations and wire names** (`wire_type.h`, `session.h`, `stub_msgs.h`, the
   negative tests) must follow the moves. The SQE tests are the gate.
5. **Consumers following the move:** the type map must be complete. Every old fully qualified name is either mapped
   or listed as deleted; the moves tool fails otherwise.

### Task 1: Parser spans and the type-move tool

**Files:**
- Modify: `tools/idl/parser.py`, `tools/idl/model.py` (each declaration gets `span: (start, end)` into the file text,
  covering its leading comments and annotations).
- Create: `tools/idl/moves.py`, `tools/idl/tests/test_moves.py`, `tools/idl/tests/fixtures/moves_*`.
- Modify: `tools/idl/__main__.py` (`moves` subcommand).

**Interfaces:**
- `parse_file` / `load_schema` set `decl.span = (start, end)`, character offsets into the file text:
  - `start` is right after the previous declaration's end (or the enclosing `{`), skipping whitespace, so the leading
    comments and annotations belong to the declaration;
  - `end` is after its closing `;`.
- `moves.compare(old: Schema, new: Schema, renames: dict[str, str], deleted: set[str]) -> Report`.
  - `Report.mapped` is the list of (old, new) pairs;
  - `Report.deleted` the deleted names;
  - `Report.problems`: a surviving old name without a new one, a new name without an old one (except types listed as
    new), and layout differences.
  - Layout equality means, after mapping every fully qualified type name through `renames`: the same members (name,
    type, optional, array) in order; for enums, the same enumerators and values; for unions, the same discriminator
    and cases; for typedefs and consts, the same type and value.
- CLI: `python3 -I tools/idl_cli.py moves --old <dds_root> --new <dds_root> --spec tools/idl/moves_0_11.json --json <out> --markdown <out>`.
  It exits 1 on any problem.

### Task 2: The move list and `restructure.py`; apply it

**Files:**
- Create: `tools/idl/moves_0_11.json`, `tools/idl/restructure.py`, `tools/idl/tests/test_restructure.py`.
- Generated and committed: `src/dds/tcn/**` (replaces `src/dds/custom/**`).

**Interfaces:**
- `moves_0_11.json`:
  - `{"files": [{"path": "tcn_types/msg/Geometry.idl", "module": "tcn_types::msg", "decls": ["tcnart_msgs::msg::Vector2", …]}, …], "deleted": [...], "copied_whole": [...]}`.
  - Files that only move (for example `tcnart_msgs/msg/PoseTracking.idl` stays) list their own declarations, so every
    surviving declaration appears exactly once.
  - A file may carry a `"header"` text, the file's top comment.
- `restructure(old_root: Path, spec: dict, new_root: Path) -> dict[str, str]` returns the rename map `{old fq: new fq}`.
  For each new file it:
  1. concatenates the original text of the listed declarations, in the listed order;
  2. rewrites every qualified reference `old::fq::Name` to its new name;
  3. qualifies every unqualified reference to a type that is now in another module, by token replacement on member
     and discriminator type positions only, using the parser's member lists to know which tokens are types;
  4. computes `#include "<new path>"` for every type the file references from another file;
  5. wraps the result in `#ifndef <PKG>_<KIND>_<FILE>_IDL` and `module a { module b { … }; };`.
- The script runs once. Its output is committed, and the script stays in `tools/idl/` as the record of the move.

- [ ] **Step 1: Write the failing tests** (`test_restructure.py`, on a fixture tree):
  - `test_split_and_requalify`: types A (with a comment) and B from `old/p/msg/T.idl`, where B uses A, are split into
