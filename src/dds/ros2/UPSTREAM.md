# ROS 2 interfaces (generated)

Everything in this directory except this file is generated by `tools/ros2` from upstream ROS 2 sources, and is never
edited by hand (decisions §5, R2–R6). What it contains:
- **IDL** for every package of every tier, with the derived service and action types;
- a **`CMakeLists.txt`** per package;
- **`ros2_types.json`**, installed as `share/tcn_schema/ros2_types.json`;
- **`UPSTREAM.lock`**, the pinned sources.

## Source

- **Distro:** ROS 2 **Jazzy Jalisco**, the LTS for Ubuntu 24.04.
- **Pins:** `UPSTREAM.lock` holds, for each repository, the tag of its Jazzy *release* version (for example
  `common_interfaces` `5.3.8`) and the commit it resolves to. It also records the rosdistro commit those versions
  were read from.
- **Distros used only for hashes:** `hash_distros` (Kilted, Lyrical).

## Tiers

| Tier | Packages | Built by default |
|---|---|---|
| `base` | builtin_interfaces, std_msgs, geometry_msgs, sensor_msgs, service_msgs | yes |
| `core` | nav_msgs, trajectory_msgs, diagnostic_msgs, visualization_msgs, shape_msgs, std_srvs, stereo_msgs, unique_identifier_msgs, action_msgs, rcl_interfaces, lifecycle_msgs, rosgraph_msgs, statistics_msgs, tf2_msgs, type_description_interfaces | yes |
| `manipulation` | control_msgs, controller_manager_msgs, moveit_msgs, object_recognition_msgs, octomap_msgs | no |
| `navigation` | nav2_msgs, geographic_msgs | no |
| `perception` | vision_msgs, pcl_msgs | no |

- **Selecting tiers:** CMake `-DTCN_SCHEMA_ROS2_TIERS="base;core;manipulation"`, or conan
  `-o tcn_schema/*:ros2_tiers="base;core;manipulation"`.
- **All tiers** are generated and committed; only the selected ones are built.
- **`service_msgs` is in `base`:** `sensor_msgs` has a service, and every service's `_Event` type needs it.

## What the generator does

- **Mapping:** the same type mapping as rosidl's msg → IDL conversion, including the `<Name>_Constants` modules and
  `@default`.
- **Every struct is `@final`:** it stays XCDR1 (`00 01`), byte-compatible with ROS 2 (decisions E2).
- **Upstream file names** (`builtin_interfaces/msg/Time.idl`), each file with an include guard.
- **Fixed arrays** are member declarators (`double covariance[36];`) instead of rosidl's typedefs. Identical on the
  wire.
- **Services:** `Foo_Request`, `Foo_Response`, `Foo_Event`.
- **Actions:** the ten structs rosidl derives: `_Goal`, `_Result`, `_Feedback`, `_SendGoal_Request/Response/Event`,
  `_GetResult_Request/Response/Event`, `_FeedbackMessage`.
- **Two fastddsgen 3.0.0 workarounds:**
  - **Keyword field names** are escaped identifiers (`_map` is the field `map`).
  - **Name collisions:** a service or action named like a message it includes gets a `Service` / `Action` file
    suffix (`control_msgs/action/GripperCommandAction.idl`), because fastddsgen overwrites the header otherwise.
    Type names are unchanged.

## ros2_types.json

One entry per type: messages, services and actions, and their parts.

```json
{"ros_name": "std_msgs/msg/String", "kind": "msg", "package": "std_msgs", "tier": "base",
 "dds_name": "std_msgs::msg::dds_::String_", "cpp_name": "std_msgs::msg::String",
 "hashes": {"jazzy": "RIHS01_df66…", "kilted": "RIHS01_df66…", "lyrical": "RIHS01_df66…"}}
```

- **`kind`** is `msg`, `srv`, `action`, `srv_part` or `action_part`.
- **`hashes`** are RIHS01 type hashes, as rmw_zenoh puts them into key expressions, per distro. A distro is missing
  when it does not have the type (`geometry_msgs/msg/Pose2D` has no Lyrical hash).
- **Two distros can talk about a type when its hashes are equal.**
- **The hashing** is a port of `rosidl_generator_type_description`. `tools/ros2/tests` checks it against all 176
  hashes shipped in 11 Jazzy binary packages.

## Refreshing

```
python3 -I tools/ros2_cli.py refresh                       # regenerate from UPSTREAM.lock
python3 -I tools/ros2_cli.py check                         # fail if the committed tree differs from upstream
python3 -I tools/ros2_cli.py refresh --update-lock         # re-resolve the pins from rosdistro (master)
python3 -I tools/ros2_cli.py refresh --hash-distros kilted,lyrical
```

- **Network:** only these commands use it; the build does not. Checkouts are cached (`--cache DIR`).

**Policy (R7):**
- The tree tracks one LTS. Moving to the next one (Lyrical, together with Ubuntu 26.04) is a scheduled change that
  can alter ROS types whose upstream definition changed. It is announced like a break for those types.
- Other distros are reached through the hashes in `ros2_types.json`.
